# 比較実験 3: PDF を文字でしか読めない AI は、同じ 30問に答えられるか

2026-10-18 実施。[比較実験 2](llm-baseline-hard.md) では、カレンダーが PDF や画像の中にしかない 5自治体で、ウェブ検索だけの AI (Claude Opus 5.5) に 30問を聞きました。
そのとき AI には、保存された PDF を「ページの画像として」開くことを許していました。Opus は 30問すべてに正しく答えました。
今回は同じ 30問・同じ正解で、**PDF や画像を開くことを禁止**しました。AI が見られるのは、ウェブ検索とページ取得が返す文字だけです。
知りたいのは、gomisute-gps のデータを作るときに、PDF を文字として取り出すだけで足りるのか、ページを画像として読む必要があるのか、です。
生データ (問題・正解・回答全文・使った道具・取得の仕方・採点) は [llm-baseline-textonly.json](llm-baseline-textonly.json) にあります。

## 前回との違い

| | 比較実験 2 (前回) | 比較実験 3 (今回) |
|---|---|---|
| 問題と正解 | 5自治体 30問。正解は 2人の独立した読みが一致したもの | 同じ (変更なし) |
| 使える道具 | WebSearch、WebFetch。WebFetch が保存した PDF を Read で開き、ページを画像として見てよい | WebSearch、WebFetch だけ。**Read は一切使わない** (保存された PDF・画像も開かない) |
| 聞き方・出力 | 1問ずつ別のエージェント。回答文と JSON | 同じ。指示の道具の行だけを変えた |

## 方法

- **答える側**: Opus 5.5 に、同じ 30問を 1回ずつ聞きました。1問ずつ別のエージェントです。手元のデータや gomisute-gps は使わせていません。
- **確認**: 43件の記録 (採点した 30件と、やり直しで捨てた 13件) をすべて調べ、**Read の呼び出しが 0回**であることを確かめました。使った道具は WebSearch・WebFetch (と、それを読み込む ToolSearch) だけです。
- **検索回数の上限によるやり直し**: この環境では、WebSearch が 1ターンあたり 200回まで (そのターンに動くエージェント全体で共有) に制限されます。上限に当たったエージェントには「検索をやめて、手持ちの情報で答えよ。外部の変換サービスも使うな」と返ります。
  多くのエージェントを同時に動かしたとき、13件がこれに当たりました。この 13件は捨て、同時に動かす数を減らして聞き直しました (村上 M2 は 2回やり直し)。採点した 30件には、上限に当たったものはありません。捨てた回答も JSON に残しています。
- **採点**: 前回と同じく、その日に出せる品目の組み合わせが正解と同じか (正解 / 誤り / 答えられず / 読めないまま推測して当たり)、地区が合っているかを見ました。
  今回は次の 2つを加えました。
  - 「**一部だけ**」: 出せる品目の一部をはっきり答え、残りは「確認できない」と書いた回答 (1件)。「A か B のどちらか。どちらかは分からない」は「答えられず」に数えました。
  - 「**拠り所**」: 答えを出した回答が何を元にしたか。今年度の公式の日程 / 今年度の日程を第三者が写したもの / 規則からの推論 / 昨年度以前の表や文書。
  - 「推測で当たり」は、今年度のカレンダーを読めなかったと書いたうえで「見込み」「可能性が高い」「おそらく」として正しい答えを出したものです。外れた推測は「誤り」に数えました。
- 付随情報 (前後の収集日、袋、時刻、電話番号など) の照合は、今回はしていません。

## 文字としては何が取れたか

この環境の WebFetch は、PDF の中身をそのまま要約役のモデルに渡すだけで、文字の層があっても取り出しません。採点した 30件で PDF を直接取得したのは 163回です。
返ってきたのは、どれも「圧縮されたデータとメタデータしかない」という返事か、404 などのエラーで、日程の中身が取れた回は 1回もありません。
文字の層がある PDF (宮崎市のエリア検索表、東海村の令和7年度の日割表) でも同じです。PNG や JPEG の画像も読めませんでした。

Opus は 30問中 12問で、外部の変換サービス r.jina.ai を通して PDF を取得し、PDF の文字の層を取り出しました。Google ドキュメントのビューアなども試しましたが、何も取れませんでした。

| 自治体 | PDF を直接取得 | r.jina.ai を通した場合 | ほかに文字で見つかったもの |
|---|---|---|---|
| 新潟県村上市 | 何も取れない | 日付の数字と一部の品目名。燃やすごみとプラはマスの色とアイコンだけなので、どの日がどの品目か結びつかない | 地区の一覧 (HTML)、カレンダーの表題 (「緑町含む」「緑町除く」) |
| 北海道旭川市 | 何も取れない | カレンダーは 0文字。外国語版の「分別の手引き」の曜日表は取れた | 地域→パターン表 (HTML)、民間サイトの令和4〜5年度の曜日表、過去の年末年始の案内 |
| 宮崎県宮崎市 | 何も取れない (文字の PDF のエリア検索表も) | エリア検索表 (町名→北A など) は取れた。カレンダーは 0文字 | 有志が公開した令和8年度カレンダーの Google カレンダー版、まとめサイト、民間サイトの令和5年度の曜日表 |
| 宮城県女川町 | 何も取れない | 凡例の文字 (黄色の日・水色の日の行政区) と、資源ごみの表の 1桁の日付だけ。色は取れない | 町のページの分別の説明 (10月からのプラ) |
| 茨城県東海村 | 何も取れない (日割表の PNG も) | 令和8年度の日割表は 0文字。令和7年度の日割表は取れた。村の地域検索ページ (JavaScript で表示) を文字にでき、地区ごとの日付が出た | 過去の年末年始の案内 (検索結果の抜粋) |

## 答えを出した回答は、何を元にしていたか

答えを出した 16問 (正解・推測で当たり・一部・誤り) の拠り所:

| 拠り所 | 正解 | 推測で当たり | 一部 | 誤り |
|---|---|---|---|---|
| 今年度の公式の日程 (文字) | 1 (東海村 舟石川駅西) | | | |
| 今年度の日程を第三者が写したもの | 3 (宮崎 橘通西・橘通東・大塚町) | | | |
| 規則からの推論 (曜日の組、第5週、年末年始) | 1 (旭川 旭町) | 4 (村上 坂町、旭川 6条通、宮崎 曽師町、東海村 照沼) | | 1 (東海村 真崎) |
| 昨年度以前の表・文書 | 1 (東海村 亀下) | 2 (旭川 永山9条、春光台) | 1 (東海村 竹瓦) | 2 (宮崎 青島、船塚) |

- **今年度の公式の日程を文字で読めたのは 1問だけ**です。東海村の地域検索ページは JavaScript で結果を表示するため、WebFetch では結果の表が空でした。r.jina.ai を通した 1回だけ、舟石川の地区ごとの日付が文字で出ました (ページに年度の表示はなく、Opus は曜日が合うことから令和8年度と判断した)。
- 宮崎の正解 3問は、有志が市のカレンダーを写して公開している Google カレンダーと、令和8年度の北Bカレンダーを元にしたまとめサイトから取りました。地区 (北A・南A) は、r.jina.ai で取ったエリア検索表の文字から決めました。
- 残りの答えは、規則や昨年度以前の表からの推測です。

## 失敗の型 (具体例)

1. **読めずに答えない** (14問)。ほとんどの回答が「PDF の中身を読み取れませんでした」と書き、公式の PDF の URL と電話番号を案内して終わりました。
   - 村上市では 6問中 5問で答えませんでした。r.jina.ai で日付と品目名の文字を取った回もありましたが、燃やすごみとプラはアイコンと色で示されているため、「日付と品目を結びつけられない」としました。
   - 女川町は 6問すべてで答えが出ませんでした。凡例の文字から「針浜は黄色の日の地区」までは分かっても、どの日が黄色かは色なので取れません。
   - 旭川の隔週の日 (永山4条 12/24、3条通 1/11) では、民間サイトの曜日表から「燃やせないごみ か 紙製容器包装・段ボール のどちらか」まで絞りましたが、その日がどちらの週かは決められませんでした。
2. **昨年度以前の表で答えて外れる** (2問、いずれも宮崎)。民間サイトの令和5年度の表と、令和8年度の市のカレンダーでは曜日が違います (市の令和8年度のページには「ルートが変わります」とある)。
   - 青島2丁目 11/16: 令和5年度の民間の表 (「青島 燃えるごみ 毎週月・木」) から、燃えるごみ (燃やせるごみ) の日と答えた (「可能性が高い」と添えた)。正しくは南Aの第3月曜で、燃やせないごみ・金属類・古布・古紙。
   - 船塚2丁目 10/30: 令和5年度の民間の表 (燃えるごみ 火・金) から船塚を南エリアとし、有志の南A・南B のカレンダーから「出せるのは燃やせるごみだけです」と答えた。正しくは北Aで、この日はプラスチック製容器包装だけ。
     この回答どおりにすると、燃やせるごみを収集のない日に出し、プラを出しそびれる。
   - 30件のうち、出す品目を誤らせうる主回答は、この船塚・青島の 2件と、下の真崎の 1件の計 3件です。ほかに、違う地区のカレンダーを案内した回答が 1件あります (下の 5)。
3. **文字にした表の列を取り違える** (東海村 真崎 1/4)。令和7年度の日割表を r.jina.ai で文字にすると、表の列がずれます。資源物と燃えないごみの組を取り違え、「燃えないごみ・粗大ごみの可能性が高い。資源物は出せない見込み」と答えました。
   正しくは、1/4 は燃えるごみと資源物で、燃えないごみは 1/5 です。
4. **一部だけ** (東海村 竹瓦 12/25)。「燃えるごみ」とだけ答え、資源物は「確認できない」としました (正しくは燃えるごみと資源物)。
   検索の上限で捨てた最初の回は、同じ問題で竹瓦を「月・木の地区」とし、「燃えるごみの日ではない可能性が高い」と逆の答えを出していました。
5. **地区の取り違え** (村上 岩船駅前 11/25)。「岩船駅前は岩船地区なので、岩船・瀬波（緑町除く）・山辺里・上海府地区のカレンダー」と案内しました。正しくは神林地域の南部地区です。
   案内されたカレンダーでは 11/25 は燃やさないごみの日です。前回 (画像で読める) はこの罠を避けていました。今回も、捨てた最初の回は神林南部を正しく挙げていました。
6. **年末年始・第5週の推測** (推測で当たり 6問)。今年度のカレンダーを読めないまま、過去の年末年始の案内や曜日の規則から「収集はない見込み」と答えて当たりました。
   例: 旭川 6条通 12/30 (「2022年末と2025年末は、30日は火・金の地区だけ」)、春光台 1/4 (「曜日の並びが同じ 2015〜16年」)、宮崎 曽師町 12/29 (「第5火曜なので何もない」、ただし北Aか北Bかは決められず)。

## 結論

- **PDF を文字として取り出すだけでは、この 5自治体のカレンダーはほぼ読めない。** 前回の予想どおりでした。
  Opus でも、今年度の公式の日程を文字で読んで答えられたのは 30問中 1問 (東海村の地域検索ページ) だけで、はっきり正解と言えたのは 6問です。画像として読めた前回の 30問から大きく落ちました。
- **だから gomisute-gps のデータを作るときは、PDF をページの画像として読む必要がある。** 画像として読めば Opus は 30問すべて正しく読めた (比較実験 2)。
  文字の層を取り出すだけの処理 (PDF からのテキスト抽出) で作ると、色・アイコン・スキャンで書かれた日程は抜け落ちる。
- **読めない回は、たいてい「答えない」で終わった。** 「高い」自信は一度も示さず、30件すべてが確認を勧めていました。誤った答え 3件も、どれも根拠にした資料 (古い表など) を示していました。
- **出た答えの多くは、昨年度以前の表・第三者の写し・規則からの推測だった。** そのため年度ごとの変更に弱く、令和5年度の表と令和8年度で曜日が違う宮崎市で 2件が外れました。誤り 3件は、どれも古い表か、文字にした表の取り違えが原因です。
- **手間は前回よりさらに重い。** 1問あたり約37回の検索・取得 (前回の約4倍)、約6分 (前回の約4倍) をかけ、外部の変換サービスや有志の Google カレンダーまで探しました。
- データを作るときに気をつけること (前回の結論に加えて):
  1. **年度ごとの有効期間**: 昨年度以前の表は、曜日が変わった所で外れる。データに年度と出典の日付を持たせ、古い表を混ぜない
  2. **第三者の写しに頼らない**: 宮崎では有志が市のカレンダーを Google カレンダーに写して公開していた。機械で読める日程の需要がある証拠だが、公式ではなく、更新される保証もない。データは公式の PDF から作る
  3. **隠れた公式データ**: 東海村は地区ごとの日付を検索ページに持っているが、JavaScript で表示されるため、ふつうの取得では空になる。こうしたページも出典になりうる
- 次にすること: この 5自治体で、Opus に公式の PDF をページの画像として読ませてデータを作り、正解 (2人の読みが一致したもの) と照らし合わせる。

## この実験の限界

- 5自治体・30問で、1問を 1回だけ聞いた (採点したのは 1回分)。捨てた回とやり直した回で答えが変わった問題があり (東海村 竹瓦、村上 岩船駅前)、ばらつきは小さくない
- 検索回数の上限に当たった 13件を捨てて聞き直した。捨てるかどうかは答えの中身ではなく上限に当たったかで決めたが、やり直しは同時に動かすエージェントを減らして行った
- r.jina.ai は、エージェントが自分で見つけた外部の変換サービスです。PDF の文字の層を自前で取り出せる AI なら、だいたい r.jina.ai が返したものを見られる。そうした手段が何もない AI は、ほぼ何も読めないはず
- 正解は前回と同じで、Claude のエージェント 2人の独立した読みが一致したもの。人間の目では確かめていない
- 付随情報 (前後の収集日、袋、時刻、電話番号など) の照合はしていない
- 民間サイト・有志のカレンダー・東海村の検索ページは、2026-10-18 以降に変わりうる
- 近畿・中国・四国の自治体は入っていない
