# 全国対応の計画 (案): 離島を含む 1,741 自治体

2026-10-18。作者 firemio の方針「本命 (Cloudflare Worker) で実装し、日本のすべての地区を入れる。離島も含めて」を受けた計画案。
数字は 4 本の調査と批評 (Claude のエージェント。出典つき) による。見込みの数字は幅で書き、確かさが低いものはそう書く。

## 1. 「すべての地区」の約束 (答えの種類)

全国のどの地点・住所を聞かれても、次の 5 つのどれかで必ず答える。推測で日付を言うことはしない。

| 種類 | 中身 | 例 |
|---|---|---|
| 1. 日付で答える | その地区のその日の品目 (公式カレンダーの日付、有効期間つき) | 金沢市、女川町 (行政区が分かる所) |
| 2. 候補を返して聞き返す | 地区の候補と、確かめる項目 (番地・自治会・集落・行政区) | 地区が分かれる町、自治会で決まる所 |
| 3. 規則と問い合わせ先 | 曜日の規則や公式ページの文、窓口 (日付は言わない) | 日付が公開されていない島 (女川町 江島)、アプリだけの町 |
| 4. 公の収集が無い | 自家処理の地域、持ち込みだけの町 | 環境省の調査で自家処理人口のある 32 市町村、上勝町 |
| 5. 対象外 | 所属未定地、北方領土、竹島・尖閣・硫黄島・南鳥島・沖ノ鳥島 | gps2city がコードを返しても答えない |

**完了の定義**: 1,741 自治体すべてに記録があり、種類 1 の人口の割合を毎回公表する。

## 2. 調べて分かったこと

- **国の標準は無い**: デジタル庁の自治体標準オープンデータセット (31 種) に、ごみ収集日・収集区域のデータは無い (分別方法一覧と集積場所一覧だけ)
- **機械で読める公式データは少ない**: 東京・埼玉 125 自治体の独立調査で 9.6%。全国では 3.5〜9% の見込み (確かさ低)。
  多いのは文字の PDF (35〜55%)、HTML の表 (20〜45%)、画像や輪郭線の PDF (10〜25%)
- **先行例**:
  - [tecolicom/japan-gomi-data](https://github.com/tecolicom/japan-gomi-data) (CC BY 4.0、2026-07〜): 38 自治体の収集データ (ABR の町字 ID に対応)、127 自治体の形式の調査、PDF の色で読む道具。連携すべき相手
  - 5374 (ゴミナシ) の各地の版: 一覧に 113 件。調べた 26 件のうち、1 年以内に更新 10、古い 10、つながらない 6
  - [bohemian916/5374MCP](https://github.com/bohemian916/5374MCP): 金沢の 5374 のデータを返す MCP サーバー (2026-04〜)。README で触れる
  - 福井県は県内 17 市町すべての収集日 CSV を 1 ページで公開 (曜日の規則)
  - 民間アプリ (さんあ～る 247、ごみスケ 約150 など) のデータは再利用できない。使わない
- **自治体と島**:
  - 自治体 1,741 (市 792・町 743・村 183・特別区 23)。北方領土の 6 村は別に「対象外」として持つ
  - 有人の離島 417 (うち離島振興法などの指定 305)。指定の有人島を含む自治体 142、全域が島の自治体 72
  - gps2city (N03) は最も遠い島まで当てる。一方、ABR の地番の位置が無い島の町村が 7 ある (礼文・利尻・利島・青ヶ島・粟島浦・知夫・渡名喜)
  - 公開された日付が無い島がある (女川町 江島など)。収集の無い島もある (竹富町 新城島(下地)・嘉弥真島など)
- **地区の決め方は自治体ごとにばらばら**: 町丁目・大字の一覧 (55〜75%)、自治会・行政区・集落 (15〜30%。境界は公開されないことが多い)、
  町全体で 1 つ (5〜15%。小さな町や島)、集積所ごと (少数)。収集区域の図形を公開しているのは草津市など、ごく少数
- **Cloudflare**: Workers Paid ($5/月) で足りる。MCP は状態を持たない Streamable HTTP (公式の createMcpHandler か、手書きの約 150 行)。
  データは R2 に自治体ごとのパック (金沢で約 2.5MB、女川で約 20KB。全国で 0.3〜1.5GB の見込み)、変更監視の状態は KV、記録は D1。
  gps2city へは Service Binding (追加の料金なし)
- **費用 (データづくり)**: 女川 1 町を作るのに API の定価で $21.28 (Opus のエージェント 15、29分)。いまのやり方で全国を作ると、
  1 回で $34K〜$107K (中央 $70K、約 1,050 万円)、毎年の更新で $31K〜42K の見込み (確かさ低)。
  道具の作りを軽くし (エージェントの土台の指示が費用の約 38%)、一括 API を使えば、中央で $32K〜45K まで下がる見込み

## 3. 作り方

1. **Worker (本命)**: Python は「作る側」(取得・読み取り・検証・パック作り) に残し、答える側を TypeScript の Worker に移す。
   住所→地区は作る側で全部の住所について計算しておき、Worker は引くだけにする (金沢の区域表の解析を Worker でやり直さない)。
   緯度経度は gps2city で自治体を決めてから、その自治体のタイル (約 500m の重なりつき) だけを読む
2. **全自治体の台帳**: 1,741 自治体 + 対象外の行。公式サイト (Wikidata と J-LIS を突き合わせ、lg.jp を優先)、ごみのページ、窓口、
   答えの種類 (§1)、元の資料と最後の確認日。まず全自治体を種類 3 (公式ページと窓口を案内) で埋め、そこから種類 1・2 に上げていく
3. **読み取りの型を 5 つにする**: CSV・iCal / HTML の表 / 文字の PDF / 色・画像の PDF / 曜日の規則の大都市。型ごとに、2 人の独立した読みと、
   コードによる突き合わせ、食い違いの裁定、変更監視をそろえる (自治体ごとの手作りの Python はやめる)
4. **試し (パイロット)**: 新しい型で女川町を作り直して 324 マスが一致することを確かめ、旭川・宮崎・村上・東海村、横浜・大阪を作って費用を実測する。
   そのあと県ごとに広げる (島の多い県は、島ごとの日程と「公開されていない」の記録を先に作る)
5. **順番の案**: 人口の多い順 (上位 100 自治体で人口の約半分) と、ウェブだけの AI が答えられない所 (PDF だけ、年度の途中で変わる所) を先にする
6. **守ること**: 各サイトに 1 秒 1 回まで、連絡先つきの User-Agent、ボット対策は回避しない。robots.txt は原則守る (作者 firemio の判断で、2026-10-19 から robots.txt で禁止された自治体のサイトも取る。破って取った数は結果に記録する)。読めない所は窓口に問い合わせる (人の作業の待ち行列)。
   民間アプリのデータは使わない。各自治体の利用規約を台帳に記録し、出典と「公式ではない」の断り、訂正の窓口を出す

### 6.1 構造 (凡例・行・列・結合したマス) も DeepSeek に見つけさせた

[nationwide/pilot/deepseek_onagawa_structure.py](../nationwide/pilot/deepseek_onagawa_structure.py)。読み取り役 2 人が別々の月の表のページから構造を読んだ。

| | A (4月のページ) | B (10月のページ) |
|---|---|---|
| 列の見出し (4 列) | 正しい | 正しい |
| 行の見出し (6 行) と色の凡例の行政区 | 正しい | 「小屋取」を「小屋敷」と読み違えた |
| 結合したマス | 「結合なし」と答えた (誤り) | 下の 2 行で 2 列の結合と答えた (誤り。正しくは全行で 2 列、下の 2 行は 3 列) |

- 2 人の答えが食い違ったので、そのまま採られることはない (裁定に回る)。ただ、**結合したマスを画像から見つけるのは、このモデルには難しい**
- 一方、PDF の罫線 (PyMuPDF の find_tables) からは、表の位置と、結合したマス (日付の行で「ペットボトル以外…」と「燃やせないごみ」が 1 つのマス、
  下の 2 行は「缶・びん…」も含めて 1 つのマス) を機械的に割り出せた。数字は字形が特殊でテキストとしては読めない (画像で読む必要がある)
- **方針**: 表の形・結合・色はコードで割り出し (PDF の罫線、画像の線と色)、見出しの文字と 1 マスずつ切り出した数字だけを LLM に読ませる。
  2 人の読みを比べ、食い違いだけを強いモデル (または人) が裁定する

## 8. 読み取りは LLM がする (2026-10-21、作者 firemio の決定)

日本語の文の読み取り・解釈は LLM がする。Python の決まり (正規表現) で読む作り (`nationwide/readers/`) は、8 回直しても穴が残ったので消した。
