# 比較実験: ウェブ検索だけの AI でも、金沢のごみの日を答えられるか

2026-10-17 実施。gomisute-gps の目的は「LLM が唯一確かな情報源として使えるようにする」ことです。
では、そもそも今の AI はウェブ検索だけで正しく答えられないのか。作り込みを続ける前に、それを測りました。
生データ (質問・正解・AI の回答全文・出典・付随情報の照合結果) は [llm-baseline.json](llm-baseline.json) にあります。

## 方法

- **問題 28問**。どれも `resolve.py` が地区を確定でき、正解の地区と収集品目が検証済みの地点・日付です。
  正解は、市のページと1日ずつ照合した 2026年度カレンダー (`out/kanazawa_schedules.json`) から取りました。

  | 種類 | 数 | 中身 |
  |---|---|---|
  | 普通の日 | 10 | 町全体が1地区の町の住所。文化の日 (11/3)・勤労感謝の日 (11/23) を含む |
  | 地区が分かれる町 | 6 | 街区・番号で地区が分かれる町の住所 (駅西本町6丁目、尾張町1丁目など) |
  | 年末年始のひっかけ | 4 | 曜日の規則なら燃やすごみの日なのに、年末年始で収集が無い日 (12/31(木)・1/1(金)) |
  | 規則とずれる日 | 4 | 2027年1月だけ第N曜日の規則と違う日 (カレンダーに※印) |
  | 緯度経度だけ | 4 | 住所を言わず「今いる場所は 緯度…、経度…」と聞く |

- **答える側**: 1問ずつ別々の AI アシスタント (Claude Opus 5.5) に、利用者の言葉で聞きました
  (例: 「石川県金沢市旭町三丁目14番10号 に住んでいます。2027年1月22日(金)にはどのごみを出せますか？」)。
  使えるのはウェブ検索とページの取得だけで、手元のデータや gomisute-gps は使わせていません。
- **採点**: 出せる品目の組み合わせが正解と同じか、地区が合っているか。
  さらに、回答に含まれる付随情報 (地区の各品目の曜日、前後の収集日、年末年始、出し方、問い合わせ先など) を、
  別の検証エージェント4人がカレンダーと市のページで1つずつ照合しました。

## 結果

| 項目 | 結果 |
|---|---|
| その日に出せる品目 | **28 / 28 正解** (年末年始のひっかけ・規則とずれる日・緯度経度だけも全問) |
| 地区 | **28 / 28 正解** (地区が分かれる町も、表の街区・番号を読んで当てた) |
| 付随情報 521件 | 正しい 515・誤り 5・確かめられない 1。誤り 5件はどれも「何を・いつ出すか」には関係しない (「時刻はカレンダーのページに載っている」など) |
| 自信の示し方 | 26問で「高い」、2問で「中」。4問は確認を勧める一言つき |
| 手間 | 1問あたり平均 約18回の検索・ページ取得、約8万トークン (28問で 519回・221万トークン) |

AI がしていたこと:

- 市の「住所から地区・校下検索」と区域表 (町名一覧) で地区を出し、地区別カレンダーの表を読んだ
- 緯度経度は、国土地理院の逆ジオコーダー (と OpenStreetMap) で町名にしてから、区域表に当てた
- 1月の※印 (年末年始による日程の変更) や、地区ごとに違う年末の最終日 (12/28 か 12/29) も読み分けた
- 市の「ごみの出し方のルール」から「収集日の午前8時30分までに出してください」を引いて答えた

## gomisute-gps の方が間違っていたこと

gomisute-gps は「ごみを出す時刻は公式ページに記載なし」とし、LLM に「時刻を推測しない」よう指示していました。
実際は市の [ごみの出し方のルール](https://www4.city.kanazawa.lg.jp/soshikikarasagasu/gomigenryosuishinka/gyomuannai/1/3/3/7608.html) に
「収集日の午前8時30分までに出してください」とあります。AI 単体の方が正しかったので、`resolve.py` は出典つきで `put_out_by` を返すように直しました。
カレンダーのページだけを見て「記載なし」と書いたのが原因です。

## 結論

- **金沢のように、市のサイトに HTML の区域表とカレンダーがそろっていれば、今の AI はウェブ検索だけで正しく答えられる。**
  金沢で「AI より正確」を gomisute-gps の売りにはできない。
- gomisute-gps に残る価値は、正確さそのものより次の点にある (どれもこの実験では測っていない):
  1. **手間と費用**: AI 単体は1問に約18回のウェブ取得と約8万トークン。データを引くだけなら1回・数ミリ秒
  2. **自治体ごとのバラバラさ**: カレンダーが PDF・画像・アプリの中にしかない自治体では、ウェブ検索だけの AI が詰まる可能性が高い
  3. **小さいモデル・ウェブ検索なしの環境**: ここでは最上位のモデルが十分に調べた。軽いモデルや検索の無い環境では結果が違うはず
  4. **機械が読める形**: アプリやエージェントが毎回同じ形で使えるデータ (地区・日付・出典・ハッシュ)
- 次に測るべきこと: カレンダーが PDF・画像だけの自治体で同じ実験をする、軽いモデル (Haiku など) で同じ実験をする、
  ウェブ検索なしで同じ実験をする。AI 単体が誤る所が見つかった所から、gomisute-gps のデータを作る

## この実験の限界

- 問題は 28問で、金沢市だけ。金沢市は区域表とカレンダーが HTML で、住所から地区を探すページもある、AI にとって答えやすい自治体
- 答えたのは 1つのモデル (Claude Opus 5.5) だけで、1問に1回だけ聞いた
- 問題には `resolve.py` が確定できる地点だけを使った (地区の境目で決めにくい地点は入っていない)
- 品目の採点は語句の対応 (「缶」「ペットボトル」→ 資源など) で自動にした。回答の全文は、別の検証エージェントが1件ずつ読んで照合した
