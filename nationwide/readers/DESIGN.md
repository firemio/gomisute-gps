## 0. 要点

1. **日付が正**。規則 (「第2・4木曜日」) は、日付を作る道具と、読み違いを見つける道具にすぎない (`kz_calendar.py` と同じ考え)
2. **迷ったら日付を出さない**。決まりが 1 つでも欠けたら `answerable=false` にして、規則の文と問い合わせ先だけを返す (答えの種類 3)。
   答えない理由は `blocked_by` に書く。「収集なし」とは言わない。推し量りで埋めない
3. 規則から日付を作るのは、資料が **規則・有効期間・祝日の扱い (どの種類の休日までか)・年末年始の扱い** を全部書いていて、
   同じ期間のカレンダー (印字の日付) が無いか、もう読んだときだけ (`pending_printed`)。月ごとの規則でも、年末年始の文が 1 つも無ければ作らない (`year_end_missing`)。
   **月ごとの規則** (ただの「毎週○曜日」のほかは、すべて。第N・隔週・N週間に1回・毎月10日・季節・「1回目の月曜日を除く」・「5番目の曜日は収集なし」) は、
   **年末年始の窓 (12/15〜1/31)** と、休み (施設の点検・お盆・祝日の休み) で回が消える月の中では、その品目の回の扱いとほかの回の数え方が文で書いてあるか、印字の日付が無ければ作らない。
   金沢は 1 月に「何回目」の数え方をずらす (田上の「第2・4金」は印字が 1/15・1/29、規則どおりなら 1/8・1/22) ので、
   市全体の「年末 12月29日まで・年始 1月4日より」だけでは 1 月は決まらない。羽咋の「1/1(金)は休みのため 1/5(火)に特別収集」も、ほかの回の数え方は言っていない
4. **「後で知らせる」は印字より強い**。年末年始などの期間を名指しして「変更することがあります」「広報でお知らせします」と書いてあれば (渋谷・大田・足立)、印字の日付があっても、その期間は「不明」と答える。
   期間を名指ししない「変更する場合があります」(村田) は、日付を消さずに注意を付けるだけ (§2.6 の見分け方)
5. **方針の文は日程の本文からだけ取る**。ページの足の「閉庁日：…祝日、年末年始（12月29日から1月3日）」(塩竈) は役所の休みで、収集の扱いではない。
   キーワードのまわりだけを切り出すと、コードも LLM も同じ誤りにそろう
6. **年は曜日の並びからは決めない** (2020 年度と 2026 年度は、4 月〜3 月の日と曜日の並びがすべて同じ)。ファイルの中 (か名前) の見える年度の印と、更新の日付の両方が要る。リンクの文字にしか年が無いときと、更新の日付どうしがぶつかる (古いメタデータと新しい `Last-Modified`) ときは人が決める
7. **表の形はコードが決める**。LLM は、コードが切り出した所の文字と数字を読むだけ。パイロット (計画 §6.1) で LLM は結合したマスを見落とした。
   表の形の食い違いは LLM の多数決では決めない
8. どの値も **独立した 2 つの読み** をコードで比べ、一致したものだけを採る。HTML の 2 つ目の読みには、タグと属性を残した生の断片を渡す
   (塩竈の斜体 = 「番地により別の地区があります」、鶴ヶ島の品目は `img` の title にしか無い)。同じモデルどうしの一致は「弱い一致」として監査を多くする。
   食い違いは裁定 (強いモデル → 人 → 自治体への問い合わせ) に回し、誤った答えはデータに入れない
9. 資料の **但し書き** (「5番目の曜日に収集はありません」「（1回目の月曜日を除く）」「5〜10月のみ」) は、どれかの値が使ったことを原文の場所つきで記録する。
   使われずに残った但し書きがあれば、その品目は印字の日付でも規則から作った日付でも答えない (但し書きが月を名指ししていれば、その月だけ「不明」)
10. 地区は、町字 (町丁目・大字) に当たるものと当たらないもの (自治会・行政区・集落・班) を分け、当たらないものは聞き返す (答えの種類 2)。
    集積所の場所で決まる区分け (新宿「集積所の住所」、熊谷「集積所 所在地別」) は、地区の境目のそばでは聞き返す
11. **公開の関門は系列 (地区 × 品目 × 期間) で数える**。資料の型ごとに、正解か人の監査で 300 系列以上を確かめて誤り 0 (95% の上限 1%) になるまで、その型は公開しない。
    系列には「答えられる」(`answerable`) と「公開した」(`published` = 答えられて、関門も開いている) を別に持ち、答えの種類 1 と台帳の人口の割合は `published` だけで数える。
    公開のあとも、12・1 月・第5週・祝日を多めに抜き取って監査し、測った誤りの率を公開する
12. 費用は LLM の API で全国 1 回 **$2K〜10K の見込み**、人の手間は **300〜750 時間の見込み** (どちらも確かさ低)。人の手間が進み方を決める。
    M1 で、行あたりの食い違いの率を新宿・北区・仙台で測って直す
13. 進める順: **M1 = 土台と、文字で読める資料 (CSV・Excel・HTML・罫線のある文字の PDF)** → 文字の月表 → 輪郭線・色 → 画像。
    M1 の合格は、japan-gomi-data の tier A の 17 自治体で答えるとした (`answerable`) 系列の誤り 0、金沢の 355 系列が今のデータと同じ、女川のパイロットの読みの再現、罠の再現セットがすべて安全な結果になること (§6.2)

### 1.4 読み取りのわな (コードで見つけるもの)

- **表の形**: 七ヶ宿町の HTML の表は壊れていて、仕様どおりに rowspan を広げると 6 行ぶん日付が隣の列にずれる (行ごとに頭の 2 マスを読めば正しい)。
  登米市は rowspan・colspan が 39。色麻町は結合したマスが空で返る (上の値で埋める)。
  七尾市は Excel のマスが塗りの矩形 24,327 個で罫線が無く、`find_tables` が働かない。羽咋市は横線だけ。寄居町は線も無い
- **日付のマス**: 1 マスに 2 つの日 (24/31・23/30。葛飾・毛呂山・春日部など)。珠洲市は 8 月の表の 1 行目の土曜の列に 1/8 が入る (2 段のマス)。
  斜めに 2 品目・縞で 2 色 (柴田・伊奈・涌谷)。3 月の表に翌年度の 4/1〜4/3 (涌谷)。月の外の日が白い文字で入っている (足立)
- **文字**: 同じ文字が同じ位置に 2〜3 回 (国立「可燃ごみ可燃ごみ」、滑川「令和令和令和」)。多賀城市は文字の対応表が無く制御文字になる。
  私用の文字 (江東・台東の訳の版)。全角数字、半角の「･」(U+FF65)、ゼロ幅の空白 (塩竈 `&#8203;`)、漢数字の「二」の代わりのカタカナ「ニ」(小松「向本折第ニ」、鶴ヶ島「脚折町ニ～六丁目」)。
  日高のコース番号 10〜20 は U+2B31〜U+2B3B の矢印の字になる
- **紛らわしいもの**: 葛飾「毎月5日はごみ減量の日」、飯能「クリーンセンター混雑予想」、草加の 1 つ目の表 (カレンダーの配布場所)、
  大衡村の粗大ごみの店の表、川北町の粗大ごみの持ち込み日 (収集日ではない)、気仙沼の翌年度の下書き、朝霞の空の雛形
- **版**: 涌谷・利府・山元は令和7年度と8年度の PDF を並べて置いている。日高の CSV は 2020 年度、清瀬の PDF は 2020 年。
  七尾の令和7年度と8年度の区分表は sha256 が同じ (表を使い回した)。川越の PDF は「令和８年度」の下に白い文字の「令和２年度」がある
- **年度でない期間・年度の途中の変更**: 輪島 (10月〜3月の後期だけ)、武蔵村山 (10月〜翌9月)、新座 (13 か月)、川口 (暦年)、品川 (2025年12月〜2026年12月)、女川 (10/1 に分け方が変わった)

批評で見つかった、決まりの穴につながるわな (直し方は §10):

- **本文の外の文**: 役所の開庁時間の「祝日、年末年始（12月29日から1月3日）」が、ページの足やレイアウトの表にある
  (塩竈の令和８年度のカレンダーの案内のページ、御蔵島「開庁時間…※祝休日、12月29日～1月3日を除く」、札幌・気仙沼・大河原・山元・立川など。キャッシュの HTML の best 138 のうち 8)。
  女川の町民カレンダーでも、文字層で「年末」「年始」が出るのは原子力 PR センターの休館日の行だけ。
  秩父広域の「施設への持込みはできません」、伊奈の「クリーンセンターへのごみの搬入はできません」は持ち込みの話
- **しるしで書いた意味**: 塩竈の斜体 29 か所 (「番地により別の地区があります」。別の側はどこにも書いていない)、鶴ヶ島の `img` の title (品目)、
  新宿の「*」だけのマス (歌舞伎町1・2丁目・新宿3丁目・西新宿1丁目。清掃事務所に問い合わせ)、大田の「ー」「-」(その回は収集なし)
- **表の外の但し書き**: 新宿「月の「5番目の曜日」に収集はありません」(金属・陶器・ガラスだけ)、赤平「第5週がある月の水曜日、土曜日の収集は休み」、
  石狩「毎週 月曜日（1回目の月曜日を除く）」、東秩父「※ペットボトルは5・6・7・8・9・10月のみ第1水曜日でも出せる」、マスの中の「（祝日の収集は休み）」
- **「第N週」の 2 通りの意味**: 三郷「びん、かん（第1・3週）」、蕨「第2、4週の月2回」、美深「第1週、第3週」。
  月の何回目とも、暦の行とも読める。滝川・南幌・紋別は「当該月の第1回目」と自分で決めている (自治体によって意味が違う証拠)
- **年の分からない資料**: 江東の nenmatunenshi2019.html は「12月30日（水曜日）まで…1月4日（月曜日）から」で年が無く、2009・2015・2020・2026 年に合う
- **「変更する場合があります」**: 大田は 1 月の日付 (「ー」、1/15 …) を載せたうえで「年末年始の収集日は変更する場合があります。区報…でお知らせします」。
  渋谷も「年末年始は収集を休んだり、変更することがあります。日程が決まり次第、しぶや区ニュース等でお知らせします」(不燃ごみの節にも「（年末年始は変更あり）」)。
  どちらも期間 (年末年始) を名指しして、後で知らせると言っている。
  これに対して村田の「※ごみの収集日は変更する場合があります。」、七ヶ宿の「※収集日が変更となる場合がありますので、町の広報紙をご確認ください。」は期間を名指ししない。
  川北の「※収集日は、祝日・お盆休み・年末年始等により、一部変更になることがあります。」は期間 (お盆休み・年末年始) を名指しする。見分け方は §2.6
- **年末年始のほかの休み**: 日高「※注意 ５月４日(月)、12月31日(木)は、施設の定期点検のため可燃ごみの収集は行いません」(火・金のコースは 5/5 と 1/1)。
  利府のカレンダーは、祝日・お盆・年末年始のマスに「収集日ではありません」
- **日ごとに変わるページ**: 鶴ヶ島の `garbage.php?mode=cal&ac=1` は、取った日の月を返す (キャッシュでは 2026 年 10 月)。`Last-Modified` が無い
- **年末年始の扱いが自治体で 3 通り**: 同じ「1/1 が金曜」でも、大田は 1 回目を休みにするだけ (「ー」のあと 1/15)、羽咋は 1/5 に振り替え、金沢は 1 月の回を 1 週ずつ後ろへずらす。
  金沢の市全体の文も羽咋の振り替えの文も、ほかの回をどう数えるかは書いていない
- **否定の言い方の年末年始**: 国立「12月31日のごみ収集はありません」、美里「注意：12月31日（木）は収集しません」「1月1日（金）は収集しません」、
  鶴ヶ島「12月29日から1月3日の収集はありません」。「休み」「変更」などの言葉を含まないので、但し書きの印 (§3.8) が「ありません」「しません」「行いません」も拾う必要がある

## 2. 自治体ごとの出力 (スキーマ v0.2)

1 自治体 1 ファイル `out/schedules/<lg_code>.json`。README のスキーマ v0.1 (`zone` と `schedule`) を広げたもので、
金沢市の `out/kanazawa_schedules.json` と女川町の `out/onagawa_data.json` はここに書き直せる (§2.11)。

### 2.1 全体の形

```json
{
  "schema": "gomisute-schedule/0.2",
  "lg_code": "172073",
  "name": "石川県羽咋市",
  "periods": [...],        // 有効期間と版の証拠 (§2.2)
  "partitions": [...],     // 区分け。品目ごとに違ってよい。決め方 (住む場所か集積所か) つき (§2.3)
  "districts": [...],      // 地区とその中身 (町字・自治会など) (§2.3)
  "categories": [...],     // 品目。公式の名前そのままと、大まかな分類 (§2.4)
  "schedules": [...],      // 地区 × 品目 × 期間 = 系列。日付と、答えない理由 (§2.5)
  "exceptions": [...],     // 祝日・年末年始・第5週・特別収集・注意・天候 (§2.6)
  "sources": [...],        // 出典 (§2.7)
  "watch": {...},          // 見張るもの (中身の sha256、案内のページのリンクの集まり) (§5.8)
  "contact": {...}, "put_out_by": {...}, "not_covered": [...],   // 金沢・女川のパックと同じ
  "coverage": {...},       // 答えの種類と、測った誤りの率 (§2.9・§4.5)
  "build": {...}           // 読み取り役・裁定・確かめ・但し書き・しるしの結果の要約 (§2.8)
}
```

値の 1 つ 1 つに、出典の場所 (`ref`)、使った原文 (`span`)、読みの記録 (`provenance`) を付ける。

### 2.2 有効期間と版の証拠 (`periods`)

```json
{"period_id": "fy2026", "valid_from": "2026-04-01", "valid_to": "2027-03-31",
 "basis": {"text": "令和8年度(Ｒ8年4月1日～Ｒ9年3月31日)", "ref": {"source_id": "s1", "page": 1}},
 "year_evidence": {
   "token": {"text": "令和8年度", "where": "in_file", "place": "title", "visible": true, "ref": {"source_id": "s1", "page": 1}},
   "time": [{"kind": "last_modified", "value": "2026-04-07"}],
   "conflict": null,
   "ok": true}}
```

- 年度とは限らない。資料が書いている期間をそのまま使う (輪島の後期、川口の暦年、熊谷の 1 か月)
- 年度の途中で変わる所は期間を 2 つ持つ (女川: 分け方が 2026-10-01 に変わった。西東京: 10 月始まりの期間が 2 つ)
- 期間の書かれていない資料 (七ヶ宿町、大衡村) は、`valid_from` を確かめた日、`valid_to` を null にし、`basis.kind: "undated"` とする。
  このとき日付では答えない (規則として返す。§9 の 7)
- 期間にする年の印は、題 (title・h1・h2・caption) の年度・期間の印、本文の期間の印 (「2026年4月～2027年3月」)、ファイルの名前の年度の印だけ。
  本文の年度の印だけのもの (東秩父「管内では令和8年度より…出し方を変更します」) は、変わる時期の話のことがあるので期間にしない (undated)
- `year_evidence` は §3.3 の決まりで作る。年の印 (`token`) と時の証拠 (`time`) の両方がそろわなければ `ok: false` で、
  その期間の系列はすべて `blocked_by: ["version_unproven"]` (答えない)。
  `token.where` は `in_file` (ファイルの中の見える文字) / `file_name` / `anchor_only` (リンクの文字・`anchor_context` にしか無い)。
  `time` は見つかった時の証拠すべてのリスト。ぶつかるもの (古いメタデータと新しい `Last-Modified`) があれば `conflict` に書き、`ok: false` で `version` の裁定へ

### 2.3 地区 (`partitions` と `districts`)

多くの自治体は区分けが 1 つ。羽咋市のように品目で区分けが違えば、区分けを品目ごとに持つ。
ある場所の答えは、区分けごとに 1 つずつ地区を決めて合わせたものになる。

```json
{"partition_id": "kanen", "label": "可燃ごみ［週２回の収集］", "category_ids": ["c1"],
 "basis": "residence", "basis_span": {"source_id": "s1", "page": 1, "text": "…"}}
{"partition_id": "shigen", "label": "資源ごみ・燃えないごみ［月２回の収集］", "category_ids": ["c2"], "basis": "residence"}

{"district_id": "172073-kanen-2", "partition_id": "kanen",
 "label": "火・金", "label_kind": "schedule",          // official (公式の地区名) / schedule (曜日などで呼ばれている) / derived (こちらで付けた)
 "members": [
   {"text": "本町", "unit": "machiaza", "machiaza_id": "<ABR の町字 ID>", "match": "exact", "conditions": [], "geometry": "polygon"},
   {"text": "千里浜町（大宮、白山、宇賀、金比羅、なぎさ、はまなす団地）", "unit": "machiaza", "machiaza_id": "<…>", "match": "exact",
    "conditions": [{"kind": "note", "text": "大宮、白山、宇賀、金比羅、なぎさ、はまなす団地"}], "geometry": "polygon"}
 ],
 "place_resolution": "polygon",
 "ref": {"source_id": "s1", "page": 1, "table": 1, "row": 2}}
```

**区分けの決め方 (`basis`)**:

| basis | 意味 | 例 |
|---|---|---|
| `residence` | 住む場所で決まる (「お住まいの町」「住所」で引く表) | 金沢「「あ」で始まる町にお住まいの方」 |
| `collection_point` | 集積所の場所で決まる | 新宿「集積所の住所」、熊谷「集積所 所在地別」、仙台 (ステーションの表示が正)、大田「集積所の看板で必ず確認してください」、北区の団地「集積所の表示板に記載」 |
| `unknown` | 資料に書いていない | – |

`unknown` は `collection_point` と同じに扱い、境目の見張りを掛ける (§2.9)。
理由: 集積所で決まる所を住む場所で当てると、境目の道の向かいの集積所を使う家に、別の地区の日を言い切ってしまう。

`members[].text` は資料の文字をそのまま残す。`unit` (中身の単位) と、図形への当て方:

| unit | 中身 | 図形への当て方 (`geometry`) | 例 |
|---|---|---|---|
| `municipality` | 自治体全体 | gps2city の `lg_code` | 七ヶ宿町、滑川町、青ヶ島村 |
| `ward` | 政令市の区 | gps2city の `ward` | 仙台市の区ごとの PDF |
| `machiaza` | 町丁目・大字・字を丸ごと | ABR の町字 ID → e-Stat 国勢調査の小地域の多角形 (`polygon`)。名前は address-normalize ([docs/address-normalize-schema.md](../../docs/address-normalize-schema.md)) で今の町字に寄せる | 羽咋市の町名、能美市「赤井町・西任田町…」 |
| `machiaza` + `range` | 丁目の範囲 (「青柳1から8丁目」「江北１～５、７丁目」) | 丁目ごとに広げてから上と同じ | 草加市、足立区 |
| `block_range` | 番地・街区・号・号棟の範囲 | ABR の住居表示の住所・街区の代表点と地番の代表点 (`points`)。金沢の `split_blocks.py`・`resolve.py` と同じ方法 | 仙台「あけぼの町6-2，6-10～6-17」、吉川「大字平沼1番地～316番地」 |
| `remainder` | 「上記以外」「を除く」の残り | 同じ町字のほかの行を引いた残り | 仙台「あけぼの町（上記以外）」、草加「旭町1から3丁目（旭町団地を除く）」 |
| `line_side` | 道路・線路・川の片側 | 線の図形が要る。今は当てない (`needs_line`) | 草加「国道4号バイパスの東側」、熊谷、鶴ヶ島 |
| `community` | 自治会・町内会・行政区・集落・班・公衆衛生組合 | 境界が公開されていないので当てない (`unresolved`)。女川の `place_to_gyoseiku` のような補助の表 (集会所の住所からの推定、確からしさつき) があれば候補に使う | 小松の町内会、涌谷の公衆衛生組合、女川の行政区 |
| `facility` | 団地・住宅・官舎・集積所 | 住所が分かれば `block_range` に。分からなければ当てない | 東松島「北区官舎」、武蔵村山「緑が丘33号棟」 |
| `former_municipality` | 旧町村の名前だけ | 大字との対応を資料で確かめられたときだけ `machiaza` に広げる | 丸森町の 8 地区、倉敷市の 6 地区 |
| `island` | 島 | 台帳の `inhabited_islands` と N03 の陸のかたまり (`n03_comp_id`)。島の証拠が要る (§5.4) | 塩竈市の浦戸、女川町の江島 |
| `map_only` | 地図の絵だけ | 当てない (人が図を写すか、問い合わせ) | 三芳町、毛呂山町 |

**条件 (`conditions`) の正規形**。言い回しではなく形で比べるため (§3.11)、条件は次の形だけで持つ:

| kind | 中身 | 例 |
|---|---|---|
| `range` | 番地・番・号・号棟・丁目の範囲。`unit`・`from`・`to` (終わりの無い範囲は `to: null`、「末」は `"end"`) | 仙台「6-10～6-17」「5-25～5-末」、能美「177～」、北区「浮間二丁目 9番19～31号」 |
| `except` | 除く。`of` に条件のリスト | 吉川「（51番地～52番地…を除く）」、春日部「粕壁(1〜4丁目を除く)」 |
| `remainder` | 上記以外・上記を除く | 新宿「（上記を除く）」26 行、北区「1～9番以外」 |
| `partial` | 一部・斜体。分け方が書いていない (`split_known: false`) | 塩竈の斜体 29、新宿「箪笥町（44番地の一部）」、北区の「一部」7 |
| `han` | 班。`values`・`negate` | 小松「下牧（11班・12班以外）」、川北「橘１班」 |
| `facility` | 団地・官舎・号棟。`name`・`negate` | 草加「（旭町団地を除く）」、府中「白糸台4丁目（車返団地は除く）」 |
| `line_side` | 道路・線路・川の片側。`line`・`side` | 草加「国道4号バイパスの東側」、栗原「国道4号東側」 |
| `enclave` | 飛地。`negate` | 春日部「新方袋(飛地を除く)」 |
| `note` | 地区を分けない注記 (町の中の地名・町内会の名前) | 羽咋「千里浜町（大宮、白山…）」、塩竈「≪石堂第二町内会≫」 |

- 地区の `place_resolution` は、中身のうちいちばん弱いもの (`polygon` > `points` > `needs_line` > `unresolved`)
- `partial` を含む町・番は、分け方が資料に無ければ、その町・番の全体を `unresolved` (聞き返す) にする。
  書いてある側の番地 (塩竈「石堂５～８番」) だけは `points` で決まる。理由: 「番地により別の地区があります」の「別」がどこか書いていないので、どちらの地区とも言い切れない
- `members[].match` は address-normalize の当たり方 (`exact` / `fold` / `ambiguous` / `none`)。`fold` と `ambiguous` は自動で選ばず、裁定に回す (§3.9)
- ABR の地番の位置が無い島の町村 (礼文・利尻・利島・青ヶ島・粟島浦・知夫・渡名喜) では、`points` が使えない。町全体か島で当てる
- `district_id` には、その市町村の `lg_code` を頭に付ける (組合の資料で複数の市町村を書くとき、大字の名前がぶつからないように。§5.3)

### 2.4 品目 (`categories`)

```json
{"category_id": "c2", "official_label": "資源ごみ・燃えないごみ",
 "coarse": ["recyclable", "non_burnable"], "mode": "curbside",
 "ref": {"source_id": "s1", "page": 1}}
```

- `official_label` は印字どおり (改行は空白 1 つ、全角の空白はそのまま)。言い換えない
- `coarse` は大まかな分類のリスト。japan-gomi-data の 14 の鍵 (burnable, kitchen, non_burnable, plastic, pet_bottle, beverage_can,
  glass_bottle, paper_cloth, cloth, paper, hazardous, spray_can, oversized, metal) に、
  中身の分からない資源 `recyclable` と `other` を足したもの。印字が「びん・缶」なら `["glass_bottle", "beverage_can"]` のように分ける。
  正解との比べ (§4.2) と、LLM の利用者への言い換えに使う。答えには公式の名前を使う
- 金沢の鍵は、`nonburnable` → `non_burnable`、`bottle` → `glass_bottle`、`recyclable` (あき缶・ペットボトル・プラスチック資源など) → `["beverage_can", "pet_bottle", "plastic"]` と読み替える
- `mode`: `curbside` (集積所に出す)、`station` (リサイクルステーションでの回収。登米市)、`dropoff` (持ち込み。川北町の粗大ごみ、青ヶ島村の燃えないごみ「随時」)、
  `reservation` (申し込み制)。**日付で答えるのは `curbside` と `station` だけ**。持ち込みの日を収集日に混ぜない。
  `mode` は 2 つの読みの両方が決める (島・村のページでは必ず。三宅は「持込 月・水・金」が収集の日の間に書いてある)

### 2.5 収集日 (`schedules`)

地区 × 品目 × 期間 ごとに 1 件。これを **系列** と呼び、公開の関門と監査の単位にする (§4.4)。
v0.1 の `rule_kind` (`rrule` / `segments` / `explicit`) は残すが、**`dates` を必ず持つ**。

```json
{"district_id": "172073-kanen-2", "category_id": "c1", "period_id": "fy2026",
 "dates_origin": "expanded",          // printed (印字された日付を読んだ) / listed (HTML などの日付の一覧) / expanded (規則を広げた)
 "rule": {"text": "火・金", "span": {"source_id": "s1", "page": 1, "text": "火・金"},
          "ir": {"kind": "weekly", "weekdays": ["TU", "FR"]},
          "rrule": "FREQ=WEEKLY;BYDAY=TU,FR", "exdates": ["2027-01-01"]},
 "dates": ["2026-04-03", "2026-04-07", "…", "2026-12-29", "2027-01-05", "…"],
 "unknown_ranges": [{"from": "2026-09-22", "to": "2026-09-22", "reason": "holiday_kind_not_covered", "note": "国民の休日"}],
 "answerable": true,
 "blocked_by": [],                    // 答えない理由。空でなければ answerable は false
 "gate": {"unit": "expanded", "open": false},   // この系列が属する関門の単位と、それが開いているか (§4.4 の 5)
 "published": false,                  // answerable かつ §4.4 の条件がすべてそろったときだけ true。答えの種類 1 はこれで決める (§2.9)
 "caveats": [],                       // 答えに付ける注意 (§2.6 の caveat・contingency)
 "expanded_with": ["e1", "e3"],       // 広げるのに使った例外・方針 (§2.6)
 "rule_mismatches": [],               // 印字と規則の違いのうち、例外の原文で説明がつくもの
 "provenance": {...}}
```

**規則から日付を作ってよい条件** (全部そろったときだけ `dates_origin: "expanded"`。1 つでも欠けたら `answerable: false` で、理由を `blocked_by` に書く):

1. 規則が資料に書いてあり、IR が 1 つに決まる (§3.7)。「第N週」(`ambiguous_week`)、起点の無い隔週・周期は広げない。
   起点は同じ期間の資料の日付からだけ取る (ほかの年度・ほかの資料の日付から推し量らない) → `rule_ambiguous`・`no_anchor`
2. 有効期間と版の証拠がそろう (§2.2・§3.3) → `period_unknown`・`version_unproven`
3. 祝日の扱いが書いてあり、どの種類の休日まで言っているか (`covers`) が分かる (§2.6)。
   規則の日に当たる休日のうち、覆われていない種類の日は、その日だけ `unknown_ranges` (`reason: holiday_kind_not_covered`)。
   「振替日に収集」(`moved`) は行き先 (`shift`) が書いてあること → `holiday_policy_missing`・`holiday_shift_target_missing`
4. 年末年始と休みの扱いが書いてある。ここでは規則を 2 つに分ける:
   - **毎週の規則**: IR が `weekly` で、`except_nth` も、`months`・`seasonal` の枠も無いものだけ。月の何回目かを数えないので、休みの日を抜くだけで済む
   - **月ごとの規則**: それ以外のすべて。`monthly_nth`・`monthly_last`・`monthly_day`・`calendar_week`・`biweekly`・`cycle`・`subcycle`・`months`・`seasonal` と、
     `except_nth` つきの `weekly`。石狩「毎週 月曜日（1回目の月曜日を除く）」と新宿の「5番目の曜日」は月の何回目かを数えるので、休みのあとに数え直されると抜く日が変わる。
     「毎月10日・25日」(`monthly_day`) は休みに当たった回の行き先が分からない。`biweekly`・`cycle`・`seasonal` は休みのあとに起点をずらす所がある

   (A) **どの規則にも要るもの**: その品目の年末年始について、次のどれかが本文の範囲 (§3.2) に書いてある。どれも無ければ `year_end_missing` (系列ごと答えない)。月ごとの規則でも同じで、
   年末年始の文が 1 つも無いのに窓 W の外だけを広げることはしない (東秩父はページに年末年始の記載が無いので、規則があっても種類 3):
     (i) 休みの期間、または年末の最後の日と年始の最初の日の日付 (`closure`。羽咋の可燃「12/29(火)最終で 1/5(火)から」、金沢の市全体「年末：12月29日（火曜日）まで 年始：1月4日（月曜日）より」、栗原「土日、年末年始(12月29日～1月3日)は収集しません」)。
     (ii) 窓の中の収集日・休みの日・振り替えの日の日付 (`dates`・`skip`・`makeup`。印字のマス、野々市「12月28日(月)、29日(火)…通常通り」「12月31日(木)、1月1日(金)…お休み」、羽咋の資源「1/1(金)は休みのため 1/5(火)に特別収集します」)。
     (iii) 決まっていない期間 (`deferred`。§2.6 の見分け方で決める。渋谷・大田・足立)

   (B) **毎週の規則**: (i) か (ii) があれば、休みの日を抜き、振り替えの日を足して広げる。(iii) だけなら、その期間 (日付が無ければ W) を `unknown_ranges` (`reason: deferred`) にして、外を広げる

   (C) **月ごとの規則の年末年始**: **年末年始の窓 W (12/15〜1/31)** の中は、その品目について
     (a) 窓の中のすべての回の日付が書いてある (印字・一覧)、または (b) 休みに当たる回の扱い (休み・振り替え・ずらし) **と**、ほかの回の数え方の **両方が文で書いてある** ときだけ作る。
     どちらも無ければ、窓 W を `unknown_ranges` (`reason: year_end_window`) にして、窓の外だけを広げる。窓の中の答えには、(ii) の原文を付けて返す。
     (b) の「文で書いてある」は、文が言っていることだけを数える。文から推し量った数え方は、コードと LLM の 2 つの読みがそろっても数えない (同じ推し量りでそろうのは §3.11 の「同じ弱点」の形)。
     羽咋の「1/1(金)は休みのため 1/5(火)に特別収集します」は 1/1 の回の扱いしか言っておらず、ほかの回の数え方も、資源の休みの期間も書いていないので (b) にならない (§2.10)。
     推し量りを使いたいときは、人が `policy` の裁定で資料の sha256 ごとに確かめて記録する (印字のカレンダー・自治体への問い合わせで)。
     資料の休みの期間が 12/15 より前に始まるか 1/31 より後に終わるなら、窓をそこまで広げる

   (D) **年末年始の外の休み**: 休みの日・期間 (`cancelled`・`closure`。日高「５月４日(月)、12月31日(木)は、施設の定期点検のため可燃ごみの収集は行いません」、お盆の休み) と、
     祝日の扱い (`not_collected`・`moved`) が、月ごとの規則の日を消すか動かすなら、その品目のその月を `unknown_ranges` (`reason: closure_month`) にする。
     その月の日付が書いてあるか、(C) の (b) と同じ 2 つ (消えた回の扱いと、ほかの回の数え方) が文で書いてあれば作る。
     毎週の規則は、その日を抜くか、書いてある行き先へ動かすだけでよい (日高の 5/4 は可燃 = 毎週なので、その日を抜く)。
     FY2026 では、月ごとの規則 1 系列あたり 1 年に 0〜2 か月 (月曜の第2・第3 は、成人の日・海の日・敬老の日・スポーツの日に毎年当たる)。決めつけるより不明にする方が安い
5. 同じ地区・品目・期間のカレンダー (印字の日付の資料) が出ていない。段 0 の資料の一覧にあるのにまだ読んでいなければ `pending_printed`。
   読めない (ブロック・画像が粗い・その型の読み取りがまだ無い) ときも `pending_printed` のまま。理由: カレンダーがあるなら、それが正 (§0 の 1)。規則だけで先に答えると、カレンダーにだけ書いた変更 (金沢の 1 月) を外す
6. その品目に当たりうる「使われなかった但し書き」(§3.8) と「決まりの無いしるし」(§3.6) が無い → `unconsumed_qualifier:<id>`・`markup_unhandled:<種類>`。
   但し書きが月を名指ししている (「5〜10月のみ」) ときは、系列ごと止めるかわりに、その月だけを `unknown_ranges` (`reason: unconsumed_qualifier`) にしてよい

**印字・一覧の日付にも掛ける条件**: 上の 2 (版の証拠)・6 (但し書きとしるし) と、`deferred` (§2.6。名前のある期間は印字の日付より強い) は、`printed`・`listed` の系列にも同じように掛ける。
1・3・4・5 は規則から作るときだけの条件 (印字の日付では、§4.1 の 1〜8・18 の確かめに使う)。

4 の理由: 年末年始の休みは、毎週の規則なら休みの日を抜くだけで済むが、月ごとの規則では「何回目」の数え方そのものが変わることがある (§1.4)。
金沢の `out/kanazawa_schedules.json` には、規則と印字の違う (地区, 品目, 月) が 2026年12月に 31
(プラスチック資源の「第5火曜日」の 12/29 が印字に無いもの 18、「第5木曜日」の 12/31 が印字に無いもの 13)、
2027年1月に 44 (資源 recyclable 17・プラスチック資源 plastic 17・燃やさないごみ nonburnable 10) あり、窓の外では 0。
ルールのページの市全体の文「年末：12月29日（火曜日）まで 年始：1月4日（月曜日）より」は初版の条件 4 を満たしてしまい、規則から作ると 1 月の日付を誤っていた。
窓を 12/15 からにしたのは、資料で見た年末の最後の日の早いもの (東松島の資源 12/22、川越のプラ 12/23、足立の決まっていない期間 12/24〜) を含めるため。
(D) を足したのは、休みのあとに数え直すのは年末年始だけとは限らず、窓 W の外の休みでも同じ誤り方をするため。

`unknown_ranges[].reason` の一覧: `holiday_kind_not_covered` (§2.5 の 3)、`year_end_window` (4 の (C))、`closure_month` (4 の (D))、`deferred` (§2.6)、`unconsumed_qualifier` (6)。

- 「変更になることがあります」の文は、祝日・年末年始の扱いが書いてあるとはみなさない。
  能美「祝日・振替休日などで、日程が変更になることがありますのでご確認ください」は期間を名指ししない `caveat` で、祝日の扱いにも数えない (`holiday_policy_missing`)。年末年始の文も無いので `year_end_missing`。
  川北「※収集日は、祝日・お盆休み・年末年始等により、一部変更になることがあります。」は、年末年始とお盆休みを名指しするので `deferred` (年末年始は窓 W、お盆休みは日付が無いので `deferred_undated:お盆`)、
  祝日は扱いが無い (`holiday_policy_missing`)。どちらも規則からは作らず、`rule.text` と出典と問い合わせ先だけを返す (種類 3)
- 印字された日付があれば、それが正。規則もあれば **全部の月 (12・1 月も)** で印字と比べる。比べる単位は (地区, 品目, 月)。
  その月の違う日が **すべて** 例外の原文 (§2.6 の `span`) で説明がつくときだけ、その (地区, 品目, 月) を `rule_mismatches` に入れる。
  説明のつかない日が 1 日でもあれば、その (地区, 品目, 月) を `rule_vs_printed` の裁定 (§3.12) に回し、裁定が済むまで、その月は答えない (`disputed:<item_id>`)。
  金沢の 75 か所では、規則の 12/31 (第5木曜日) が印字に無い 13 か所は、市全体の「年末：12月29日まで 年始：1月4日より」の休みの期間 (12/30〜1/3) に入るので説明がつく。
  規則の 12/29 (第5火曜日) が印字に無い 18 か所は、12/29 が「まで」の日 (収集のある日) なので説明がつかない。1 月の 44 か所は、休みの期間の外の日 (1/8・1/15・1/22・1/29) が増えたり減ったりしているので説明がつかない。
  → `rule_mismatches` 13、`rule_vs_printed` 62。
  理由: 違いを黙って `rule_mismatches` に入れると、読み違い (列の取り違え) と本当の変更の区別がつかない
- `unknown_ranges` の日は「不明」と答える (「収集なし」と言わない)。japan-gomi-data の `unknown_periods` と同じ意味。どの日も `reason` を持つ。
  `unknown_ranges` は `dates` より強い (同じ日が両方にあれば「不明」)
- RRULE などへの圧縮は、圧縮した形から `dates` に 1 日も違わず戻るときだけ付ける (金沢の `segments` と同じ確かめ)

- 方針の文は §3.2 の本文の範囲からだけ取り、どれも使った原文の `span` を持つ
- **休日の種類**: 「祝日」とだけ書いてあれば `national` だけ。FY2026 で規則の日に当たりうる振替休日 (2026-05-06 水・2027-03-22 月) と国民の休日 (2026-09-22 火) は、
  覆われていなければその日だけ不明にする。理由: 「祝日」に振替休日を含めるかは自治体で書き方が違い (羽咋はわざわざ「祝日、振替休日も」と書く)、
  1 系列あたり 1 年に 0〜3 日なので、決めつけるより不明にする方が安い (§9 の 8)
- **振替の行き先** (`shift.to`): `next_day` (次の日) / `next_weekday` (次の平日) / `next_same_weekday` (翌週の同じ曜日) / `prev_weekday` / `date` (日付で書いてある)。
  行き先が書いていなければ、その品目は答えない。理由: 行き先が分からないと、どの日に収集が増えるかも分からない
- `year_end` の `others` (ほかの回の数え方) は、文がそう言っているときだけ入れる。`makeup` の文 (羽咋「1/1(金)は休みのため 1/5(火)に特別収集します」) から
  「休んだ日を 1 回と数えているので、ほかの回はずらさない」と推し量るのは、コードと LLM の両方がそう読んでも採らない (`others: null`)。
  採るのは、人が `policy` の裁定で資料の sha256 ごとに確かめて記録したときだけ (§2.10 の羽咋)
- 例外は、規則を広げるときに使う。印字された日付を読んだときは、説明と確かめ (§4.1 の 5・6・18) に使う。印字より強いのは `deferred` だけ

**`deferred` と `caveat` の見分け方** (コードが文ごとに決める。LLM の読みとは「止める方」を採る):

1. 文の単位: 「。」・改行・箇条書きの 1 項目・「※」で始まる注を 1 つの文とする。かっこ書き (渋谷「（年末年始は変更あり）」) も 1 つの文
2. **期間の名前**: 「年末年始」「年末」「年始」「正月」「お盆」「盆休み」「大型連休」「ゴールデンウィーク」(略して「GW」)「連休」と、祭典・行事の名前 (「〜祭」「〜まつり」)。
   「祝日」「祭日」「振替休日」「休日」は休日の種類で、期間の名前に入れない (川北「祝日、祭日、お盆休み、年末年始等で」の期間はお盆休みと年末年始)
3. **後で知らせる・変わりうるの印**:
   - 変わりうる: 「ことがあります」「場合があります」「変更あり」と、その丁寧な言い方「ことがございます」「場合がございます」
     (川口「年末年始の収集日につきましては、通常の周期と異なることがございます」)
   - ほかで知らせる・まだ決まっていない: 「決まり次第」「後日」「別途」「改めて」「未定」「反映されていません」「反映していません」「広報」「区報」「市報」「町報」「村報」「ニュース」「ホームページ」
   「お知らせ」「変更」だけでは印にしない。知らせそのもの (「年末年始のごみ収集の変更についてお知らせします。年末は12月29日まで…」) が自分を止めてしまうため。
   こういう文が日付の扱いに使われずに残れば、§3.8 の洗い出し (「年末」「年始」「変更」の印) で拾われ、その品目は止まるので、取りこぼしても日付は出ない
4. 1 つの文に **期間の名前と印の両方** があれば `deferred` (その期間)。印字・一覧の日付より強い。
   同じ文の中に期間の日付があればその日付 (足立「年末(12/24～12/31)…年始(1/1～1/10)については、12月の広報やホームページ等」→ 12/24〜1/10)、無ければ年末年始・年末・年始・正月は窓 W、それ以外は `deferred_undated:<期間>`。
   当たる品目は、文のある節の品目 (節の外なら、すべての品目)。渋谷の「（年末年始は変更あり）」は不燃ごみの節にあるので不燃ごみ、「年末年始は収集を休んだり…」は全部の品目
5. 印があって期間の名前が無ければ `caveat` (村田・七ヶ宿・能美)。日付は消さない。
   キャッシュで確かめると、羽咋・村田・七ヶ宿・能美・金沢のページには 4 に当たる文が無い。当たるのは、
   川北 2 文 (「※収集日は、祝日・お盆休み・年末年始等により…」「（注）　可燃物は祝日、祭日、お盆休み、年末年始等で…」)、渋谷 2 文、
   大田「注釈：年末年始の収集日は変更する場合があります」、足立「※　令和８年年末年始のごみ・資源収集に関する内容は、12月のあだち広報でお知らせします」、
   川口「※年末年始の収集日は反映されていませんので、「年末・年始ごみ収集のお知らせ」をご覧ください」
6. 印の無い年末年始の文 (金沢「年末：12月29日（火曜日）まで」、国立「12月31日のごみ収集はありません」) は `year_end` の材料で、`deferred` にも `caveat` にもしない
7. コードと LLM の読みが違えば `deferred` を採る (止める方)。`caveat` に下げてよいのは、人が `policy` の裁定で「この文は日付の決まった期間の注意にすぎない」と決めて、資料の sha256 つきで記録したときだけ
8. 祝日・振替休日と印のある文 (能美「祝日・振替休日などで、日程が変更になることがあります」、川北の「祝日…」の部分) は、祝日の扱いが書いてあるとはみなさない (`holiday_policy_missing`)

### 2.7 出典 (`sources`) と場所 (`ref`・`span`)

```json
{"source_id": "s1",
 "url": "https://www.city.hakui.lg.jp/material/files/group/11/R8gomisyuusyunittei.pdf",
 "source_key": "https://www.city.hakui.lg.jp/material/files/group/11/R8gomisyuusyunittei.pdf",
 "found_from": "https://www.city.hakui.lg.jp/sumai_kankyou_anzen/gomi_kankyou_recycle_doubutsu/1/4644.html",
 "anchor_text": "令和8年度可燃・資源ごみ日程表 (PDFファイル: 83.3KB)",
 "anchor_context": {"heading_path": ["…"], "block_html": "…", "ref": {"source_id": "s0", "selector": "…"}},
 "title": "令和8年度(Ｒ8年4月1日～Ｒ9年3月31日)ごみ収集日程表",
 "publisher": "羽咋市", "format": "pdf_text", "pages": 1,
 "sha256": "e64fd7c337ba16b0d9b102c8ba2180ac9704251d68a99e826b53936ee4cbf3e4",
 "content_sha256": "…",
 "last_modified": "Tue, 07 Apr 2026 00:26:27 GMT", "fetched_at": "2026-10-19T03:14:18+09:00"}
```

- `sha256` は取ったバイト列のもの。記録と、読み取りの結果の使い回し (同じ sha256 は読み直さない) に使う。
  見張り (§5.8) には `content_sha256` (本文の範囲を取り出して正規化した中身のもの。HTML の「更新日」や閲覧数の行では変わらない) を使う
- `source_key` は資料を見分ける鍵。ふつうは URL。日ごとに変わるページは、パラメータと月まで入れる (鶴ヶ島 `garbage.php?mode=cal&ac=1&year=2026&month=11`。§5.7)
- `anchor_text` (リンクの文字) と `anchor_context` (見出しの道すじと、リンクを含む塊の HTML。タグつき) を必ず残す。
  地区の定義がリンクのまわりにしか無い所がある: 塩竈はリンクの文字が「資源物月曜日地区 [PDF]」で、町名の一覧 (斜体つき) はリンクのあとの文にある。
  吉川 (番地の除外)・多摩・岩沼・小金井・穴水・瑞穂 (地区ごとの町名) も、地区の名前が親の見出しやまわりの文にしか無い。葛飾区の 2025 年版はリンクの文字。
  `anchor_context` は読み取りの入力で、ほかの値と同じく 2 つの読みとしるしの棚卸し (§3.6) を通す
- `format`: §3.5 の型 (`csv` `xlsx` `html_table` `html_text` `pdf_text` `pdf_outline` `pdf_image` `js_view` `dynamic_month`)
- `publisher` は発行元。一部事務組合なら組合の名前 (§5.3)
- `ref` は値の場所: `{"source_id", "page" (1 から), "table", "row", "col", "bbox", "selector"}`。HTML は表の番号と行・列、または DOM の道すじ
- `span` は値が使った原文: `{"source_id", "selector" か "page" と "bbox", "start", "end", "text"}`。
  IR・例外・方針・地区の中身は、どれも `span` を持つ。§3.8 の「使われなかった但し書き」はこれで数える

### 2.8 読みの記録 (`provenance`)

```json
{"readers": [
   {"reader": "code.html_grid@1", "kind": "code", "inputs": {"source_sha256": "…", "selector": "…"}, "agree": true},
   {"reader": "llm.members.B@2", "kind": "llm", "model": "deepseek-flash", "prompt": "members.B@2",
    "inputs": {"fragment_sha256": "…"}, "agree": true}],
 "independence": "code_llm",  // code_llm / llm_diff_model / llm_same_model
 "status": "agreed",          // agreed / agreed_weak / adjudicated / single / disputed
 "spans": [{"source_id": "s1", "selector": "…", "text": "…"}],
 "adjudication": null}        // 裁定したなら {"item_id", "by": "code3" | "opus" | "human" | "inquiry", "at", "note"}
```

- `agreed` は、コードと LLM、または別のモデルの LLM 2 つの一致。同じモデルの LLM 2 つ (問いかけと切り出しだけが違う) の一致は `agreed_weak`。
  理由: 同じモデルは同じ字を同じように読み違える (§3.11)
- `answerable: true` にできるのは `agreed`・`agreed_weak`・`adjudicated` だけ。`single` (読みが 1 つしか無い) と `disputed` (裁定待ち) は答えない。
  `agreed_weak` の系列は監査の抜き取りを 5 倍にする (§4.5)
- 読み取り役ごとに、モデル・問いかけの版・入力 (切り出しの sha256) を必ず残す。あとで同じ弱点を持つ読みを見分けるため
- `build` には、読み取り役ごとの値の数・一致の数・裁定の数、確かめ (§4.1) の結果、洗い出した但し書きの数と使われなかったもの、しるしの棚卸し、
  `blocked_by` の理由ごとの系列の数、LLM のトークンと費用を書く (女川の `build` と同じ考え)

### 2.9 答えの種類 (`coverage`)

計画 §1 の 5 つの答えの種類を、地区ごとと自治体ごとに持つ。

| 種類 | 地区がこの状態のとき |
|---|---|
| 1. `dates` 日付で答える | 品目がすべて `published: true` (`answerable: true` で `blocked_by` が空、そのうえ §4.4 の公開の条件がそろい、系列の関門の単位 `gate.unit` が開いている) で、`place_resolution` が `polygon` か `points` (または、その場所の候補の地区がどれも同じ日付。女川の浦宿浜)。区分けの `basis` が `collection_point`・`unknown` なら、さらに境目の見張りの外 |
| 2. `ask` 候補を返して聞き返す | 日付 (`published: true` の系列) はあるが、場所から地区が決まらない (`community`、`line_side`、`partial`、番地の一部、境目の見張りの中など)。聞く項目 (番地・自治会・行政区・集積所の表示) を持つ |
| 3. `rule_contact` 規則と問い合わせ先 | 日付が無い・`answerable: false`・関門がまだ開いていない (`published: false`)。規則の文・公式ページ・窓口と、答えない理由を返す |
| 4. `no_public_collection` 公の収集が無い | 資料か環境省の調査で、自家処理・持ち込みだけと分かる |
| 5. `out_of_scope` 対象外 | 台帳の `no_service_areas.json` (北方領土・所属未定地など) |

**境目の見張り** (`basis` が `collection_point`・`unknown` の区分け):

- 場所から地区を決めるとき、ほかの地区の区域が「見張りの距離」以内にあれば、日付を言い切らずに候補を返して聞き返す (種類 2)。
  距離は金沢の `resolve.py` の `NEAR_M` (10m) + 位置の誤差から始め、集積所で決まる区分けは 30m + 位置の誤差にする
  (道の向かいの集積所を使う家を拾うため。30m は確かさ低。集積所の位置を公開している自治体で測り直す)
- この区分けの答えには、いつも「集積所の表示 (看板) を確かめてください」を付ける
- 人口の割合を数えるときも、見張りの帯の中の人口は種類 2 に数える

```json
"coverage": {"answer_type": "dates",
             "population_share": {"dates": 0.97, "ask": 0.03, "rule_contact": 0, "no_public_collection": 0},
             "population_basis": "国勢調査2020 小地域の人口",
             "blocked_series": {"pending_printed": 0, "year_end_missing": 0},
             "gate_pending": {"series": 0, "population_share": 0},
             "quality": {"unit": "pdf_text", "series_checked": 312, "series_wrong": 0, "upper95": 0.0096}}
```

- 自治体の `answer_type` は、いちばん多くの人が当たる種類。1 つの自治体の中で混ざってよい (女川町: ほかの行政区は日付、江島は日程が公開されていないので規則と窓口)
- **種類 1・2 は `published` の系列だけで数える**。`answerable: true` でも関門の単位が開いていない系列は種類 3 に数え、`gate_pending` (関門が開けば種類 1・2 になる系列の数と人口の割合) に別に書く。
  `out/schedules/` は公開の git に入るので、そこにある日付を「公開した」と取り違えないよう、パック・台帳・MCP の答えは `published: true` の系列だけを読む。
  §4.4 の条件が 1 つでも崩れたら (関門が閉じた・見張りで資料が変わった)、`published` を false に戻す
- 台帳 (`out/registry/municipalities.json` の `coverage`) には、この値と `population_share` を写す。計画の「完了の定義」の、種類 1 の人口の割合はここから数える
- `quality` は、その自治体の系列が属する関門の単位 (§4.4 の 5) で測った誤りの率。公開する

### 2.10 例

**羽咋市 (規則を広げてよい例。ただし資源の年末年始は不明)**。1 ページの PDF に、可燃の 3 群 (月・木 / 火・金 / 水・土) と、資源・燃えないの 10 群 (第1・3 と 第2・4 の 月〜金) がある。

- 有効期間「令和8年度(Ｒ8年4月1日～Ｒ9年3月31日)」は題 (ファイルの中) にあり、`Last-Modified` は 2026-04-07 (版の証拠がそろう)
- 可燃 (毎週): 群ごとに「12/28(月)最終で 1/4(月)から」「12/29(火)最終で 1/5(火)から」「12/30(水)最終で 1/6(水)から」と日付で書いてある (§2.5 の 4 の (B)) → 1 年分を `expanded`
- 資源・燃えない (月ごとの規則): 年末年始について書いてあるのは「1/1(金)は休みのため 1/5(火)に特別収集します」だけ。これで §2.5 の 4 の (A) は満たすが、(C) の (b) は満たさない:
  - 書いてあるのは 1/1 の回の扱い (`makeup`) だけで、1 月のほかの回の数え方は書いていない (`others: null`)。「1/1 を 1 回目と数えて振り替えたので、ほかはずらさない」は推し量り
  - 資源・燃えないの休みの期間も書いていない。「休みに当たるのは 1/1 だけ」と言うには可燃の群の最後と最初の日を借りることになる
    (12/28 は第2・4月曜の群の 4 回目、1/4 は第1・3月曜の群の 1 回目で、どちらも可燃の月曜の群の境目の日。資源も同じ日に収集するとは書いていない)
  - コードと LLM が同じ推し量りでそろっても、それは同じ弱点でそろった形 (§3.11) なので数えない
  - → 窓 W (12/15〜1/31) を `unknown_ranges` (`year_end_window`) にし、窓の外を `expanded`。窓の中の答えは「不明」で、1/1 の振り替えの原文と問い合わせ先を付ける。
    窓の中を答えるには、人が `policy` の裁定で、市の印字のカレンダーか問い合わせで確かめ、資料の sha256 つきで記録する
- 祝日は「祝日、振替休日も実施」(`covers: ["national", "substitute"]`)、大型連休は「通常通り」。祝日で消える回が無いので、§2.5 の 4 の (D) は当たらない。
  国民の休日 2026-09-22 (火) は名前が無いので、火曜の群ではその日だけ `unknown_ranges`
- 段 0 で、案内のページに同じ期間のカレンダーの資料が無いことを確かめる (あれば `pending_printed`)
- → 全地区・全品目を `expanded` で `answerable: true`。不明は、火曜の群の 9/22 と、資源・燃えないの窓 W。区分けは 2 つ (`kanen` と `shigen`)。
  種類 1 にするのは、単位 `expanded` の関門が開いてから (`published`)

**金沢市 (規則だけでは 12・1 月を答えない例)**。ルールのページ (`data/kanazawa_rules.html`) に、市全体の
「2026年度年末年始のごみ収集について 年末：12月29日（火曜日）まで 年始：1月4日（月曜日）より」がある。

- 燃やすごみ (毎週) は、地区ごとの規則のマスに「年末は12月28日（月曜日）まで 年始は1月4日（月曜日）から」があり、
  祝日は市の「ごみの出し方のルール」の「収集は年末年始を除く月曜日～金曜日（祝日含む）に行います」(`all_weekdays`) で決まる → `expanded`
- ほかの品目 (燃やさないごみ・資源・びん・プラスチック資源) は月ごとの規則で、市全体の文は「休みの期間」しか言っていない。
  数え方は印字のカレンダーを見ないと分からない (田上の資源「第2・4金曜日」: 規則 1/8・1/22、印字 1/15・1/29。プラスチック資源「第5火曜日」の 12/29 は印字に無い)
- → カレンダー (`data/kanazawa_cal/*.html`) を読む前は `pending_printed`。読んだあとは `printed` で、規則と違う (地区, 品目, 月) 75 か所のうち、
  12/31 (第5木曜日) の 13 か所は市全体の休みの期間で説明がつくので `rule_mismatches`、残りの 62 か所 (12/29 の第5火曜日 18・1 月 44) は
  `rule_vs_printed` の裁定で印字を正と確かめてから答える (§2.5)。カレンダーが無かったとしても、窓 W は `unknown_ranges` で、1 月を規則から作らない

**能美市 (答えない例)**。HTML の表に「可燃 月曜日・木曜日」「不燃 第1木曜日」「資源 第2・第4日曜日」などの規則がある。
年末年始と祝日は「祝日・振替休日などで、日程が変更になることがありますのでご確認ください」(期間を名指ししないので `caveat`) だけで、詳しくは地区ごとの PDF (取っていない) にある。
この文は祝日の扱いにも年末年始の扱いにも数えない。
→ `answerable: false`、`blocked_by: ["pending_printed", "holiday_policy_missing", "year_end_missing"]` (種類 3)。PDF を読めば種類 1 に上がりうる
(印字の日付には祝日・年末年始の扱いの文は要らない。§2.5 の「印字・一覧の日付にも掛ける条件」)。
「第1・第3木曜日 注：松が岡 第2・第4木曜日」は松が岡を別の地区にする。地区のマスのリンクの文字「(PDF 791KB)」は外す。

**足立区 (決まっていない期間)**。町丁ごとの曜日の表と有効期間「令和８年（２０２６年）４月～令和９年（２０２７年）３月」がある。
年末年始は「12月の広報やホームページ等をご覧ください」。→ 12/24〜1/10 を `unknown_ranges` (`deferred`) にする。
町丁ごとのカレンダーの PDF (品目はマスの色) があるので、それを読むまでは `pending_printed`。読めば `printed` にする
(カレンダーにも年末年始は無いので、12/24〜1/10 は `unknown_ranges` のまま。知らせを読んだら外す。§5.8)。

**大田区 (印字の日付に「変更する場合があります」が付く例)**。不燃ごみの 12 組 × 12 か月 × 2 回の日付が HTML の表にあり、
1 月の 1 回目は「ー」「-」(その回は収集なし。`none`)。そのうえで「年末年始の収集日は変更する場合があります。区報…でお知らせします」とある。
→ 名前のある期間の `deferred` (日付なし) なので、印字の日付があっても窓 W を `unknown_ranges` にし、区報・ホームページの知らせを読むまで 12/15〜1/31 は「不明」。ほかの月は `listed` で答える。
町丁目 → 曜日の表は PDF にあり、「集積所の看板で必ず確認してください」なので区分けは `collection_point` (境目の見張りを掛ける)。

**渋谷区と村田町 (`deferred` と `caveat` の分かれ目)**。
渋谷の「ごみ収集日」のページは、地域別の曜日の一覧表 (PDF) と「令和8年3月～令和8年11月 渋谷区資源とごみの収集日一覧表」(PDF) へのリンクの前に、
「年末年始は収集を休んだり、変更することがあります。日程が決まり次第、しぶや区ニュース等でお知らせします。」と書く。
1 つ目の文に期間の名前 (年末年始) と印 (「ことがあります」) がそろうので `deferred` (§2.6 の見分け方の 4)。次の文の「決まり次第」も、日付がまだ決まっていないことを言っている。
日付が無いので窓 W を、曜日の規則から作っても一覧表の日付を読んでも `unknown_ranges` にし、しぶや区ニュース等の知らせを読むまで 12/15〜1/31 は「不明」。
不燃ごみの節の「毎月29日・30・31日の不燃ごみの収集はありません。（年末年始は変更あり）」も、かっこ書きが同じ形なので不燃ごみの `deferred`。
同じ節の「第1（または第2・第3・第4）○曜日とは、「当該月の第1番目…の○曜日」ということです」は、第N を月の何回目と決める文 (§3.7)。
村田の「※ごみの収集日は変更する場合があります。」は期間を名指ししないので `caveat` で、カレンダー (2026年度 4～9月分・10～3月分) の日付は消さずに注意を付ける。

**女川町 (地区が自治会の単位)**。日付は町民カレンダーから `printed`。地区の中身は行政区 (`community`) なので、場所からは決めない。
既にある `place_to_gyoseiku` (集会所の住所からの推定、`certainty: likely`) で候補を出し、出す日が同じなら日付で、違えば聞き返す。江島は日程が公開されていない (種類 3)。
カレンダーの文字層で「年末」「年始」が出るのは原子力 PR センターの休館日の行だけなので、年末年始は印字の色からだけ読む (§3.2)。

### 3.2 本文の範囲と方針の文

祝日・年末年始・期間・但し書きの文は、その日程の本文からだけ取る。
理由: 役所の開庁時間の文 (塩竈「閉庁日：土曜日・日曜日・祝日、年末年始（12月29日から1月3日）」、御蔵島「開庁時間…※祝休日、12月29日～1月3日を除く」) は
「祝日」「年末年始」と日付を持つので、キーワードのまわりを切り出すと、コードの正規表現も LLM も「祝日は休み・12/29〜1/3 は収集なし」と読み、
2 つの読みがそろって誤る。そのうえ初版の条件 3・4 (祝日・年末年始の扱いが書いてある) を満たしてしまう。

HTML:

1. **本文の範囲**: `main`・`article`・`role="main"`・CMS の本文の要素 (`#main` `#contents` など。ホストごとに段 0 で決める)。
   無ければ、日程の表を含むいちばん小さな塊から、前後の同じ高さの見出しまで
2. **外すもの**: `header` `footer` `nav` `aside`、パンくず、「このページに関するお問い合わせ」の欄、文字サイズ・背景色の切り替え
   (金沢のページでは「文字サイズ変更」の「変更」が拾われる)。
   本文の中の欄は、札 (「お問い合わせ先」「関連情報」など) から次の同じか高い見出しまでだけを外す。見出しでない札は小さな塊 (600 字以下) の頭にあるときだけ欄とみなし、
   「ページの先頭へ」のような 1 行の飾りはその行だけ外す。日程の表と、4 の文・§2.6 の文・§3.8 の但し書きの文の手前で止める
   (欄の外まで外すと deferred と但し書きが消え、答えない方に倒れなくなる。川口の「お問い合わせ先」の見出しの前の「通常の周期と異なることがございます」)
3. **使い回しの部分**: 同じホストの、中身の関係の無いページ 3 つ以上に同じ文字で出る塊は外す (塊の文字を正規化した sha256 を、段 0 でキャッシュのページから数える)。
   関係の有る無しは、本文の範囲の塊どうし、またはサイトの枠 (半分以上のページに出る塊) を除いた塊どうしの重なりで決め、どちらかで重なれば関係あり
   (三鷹の 8 地区のページは、ページ全体で比べると関係なしに見え、地区に共通の方針の文が外れていた)。
   §2.6 の文と、ごみの収集の言葉と但し書きの印を持つ文は、使い回しでも外さない (「祝日も収集します。（年末年始を除く）」「年末及び1月は収集日程、時間が異なることがあります。」)
4. **方針の文のふるい**: 「開庁・閉庁・業務時間・窓口・受付・休館・開館・営業」を含む文は方針にしない。
   方針の文は「収集・回収・ごみ・資源・出す・出せ」のどれかを含むこと。
   「持込・持ち込み・搬入・受け入れ・受入」を含む文は、`mode: dropoff` の品目にだけ使う (秩父広域「施設への持込みはできません」、伊奈「クリーンセンターへのごみの搬入はできません」)
5. **場所の確かめ**: 方針の文の `ref.selector` が、日程の表と同じ節 (同じ見出しの下) にあるか、見出しがごみの収集を名指ししている節
   (金沢「2026年度年末年始のごみ収集について」) にあること。ほかの節の文は使わない

PDF:

- 方針の文は、日程の表と同じページの、表・凡例・注意の枠からだけ取る。4 のふるいは PDF にも掛ける
  (女川の町民カレンダーの原子力 PR センターの休館日の行、秩父広域の施設の受け入れの枠は外れる)。冊子は §5.2 の月の表のページと凡例・分け方のページだけ

LLM:

- 方針を読む LLM には、キーワードのまわりではなく **本文の範囲の全体** を渡す (長ければ見出しの切れ目で分け、見出しの道すじを付ける。1 回 1 万字まで)。
  答えの方針には、どれも原文の `span` を書かせ、「役所の開庁時間・施設の休館の文は方針にしない」と指示する。
  コードの読みとは、方針の値と `span` の両方で比べる (`span` が違う所を指していれば、値が同じでも食い違い)

### 3.3 版の決め方

**曜日の並びは年の証拠にしない**。2020 年度と 2026 年度は、4 月 1 日がどちらも水曜で、4 月〜翌 3 月の日と曜日の並びがすべて同じ (2 月 29 日はどちらの年度にも無い)。
だから、曜日の確かめ (§4.1 の 1・2・8) は 2020 年度のカレンダーを使い回しても全部通る (日高の CSV は 2020 年度、清瀬の PDF は 2020 年)。
江東の nenmatunenshi2019.html の「12月30日（水曜日）まで…1月4日（月曜日）から」は年が無く、2009・2015・2020・2026 年に合う。

版の証拠 (`year_evidence`) は、次の 2 つがそろったときだけ `ok`:

1. **年の印**: 年度・年の印 (「令和8年度」「R8」「2026年度」「2026年4月～2027年3月」、ファイルの名前の `R8_01.pdf`・`2026tikubetsu.xls`) が、
   **ファイルの中** (題・見出し・表の見出し・本文の見える文字。`where: in_file`) か **ファイルの名前** (`file_name`) にある。
   PDF では見える文字だけを数える (白い文字・ほかの文字の下に隠れた文字は数えない。川越の PDF の白い「令和２年度」)。
   リンクの文字 (`anchor_text`・`anchor_context`) にしか年の印が無いとき (`anchor_only`) は `ok` にせず、`version` の裁定に回す。
   理由: 案内のページのリンクの文字だけを毎年「令和8年度」に書き換え、ファイルは古いまま上げ直すことがありうる。リンクの文字は、ファイルの中の年の印とぶつからないかを見る 2 つ目の証拠にだけ使う。
   2 つの年の印がぶつかるとき、年の印が期間と合わないとき (江東の年末年始のページは URL に 2019 があり、中身には年が無い) も `version` の裁定。
   ぶつかりは、題・ファイルの名前・本文・リンクの文字のどの組でも見る (題は令和8年度でファイルの名前は R7、本文は令和2年度だけでファイルの名前は R8)。
   本文に合う印と合わない印が混じるもの (町民カレンダーの記事の「令和7年度」) はぶつかりにしない。
   暦年だけの印 (「2026年」「2026年1月」) は、年度の期間では年の印にしない (2025 年度の資料にも「2026年1月」がある)。更新日・掲載日の日付は時の証拠で、年の印にしない
2. **時の証拠**: HTTP の `Last-Modified`、ページの「更新日」、**ファイルの中の時** (PDF・Excel のメタデータの更新日。無ければ作成日) を、見つかったものすべて `time` に並べる。
   そのうち少なくとも 1 つが、有効期間の始まりの 15 か月前から有効期間の終わりまでの間にあり、**どれもその範囲より古くない** ときだけ通す。
   ぶつかるとき (`Last-Modified` は 2026 年なのに、PDF のメタデータの更新日は 2020 年: 古いファイルを上げ直したときの形) は `conflict` に書いて `version` の裁定。
   `Last-Modified` が取った時刻とほとんど同じもの (動的に作るページ) は数えず、ページの「更新日」を使う。
   時の証拠は、どれもその資料自身のもの (案内のページの「更新日」は、そこからリンクした PDF の時の証拠に数えない)。
   どれも無いか外れていれば、人が `version` の裁定で決める

さらに:

- **祝日の印の突き合わせ** (§4.1 の 14): 印字のカレンダーの祝日の印 (赤い数字・「祝」) が、その年度の祝日の表 (内閣府「国民の祝日」の CSV) と合う。
  2020 年度は東京オリンピックで 7/23・7/24・8/10 が祝日で 7/20 は平日、2026 年度は 7/20 (海の日) が祝日で 7/23・7/24・8/10 は平日なので、使い回しはここで見つかる。
  ただし祝日の印を刷っていないカレンダーや規則の表ではこの突き合わせが効かないので、上の 1・2 (ファイルの中の年の印、ぶつからない時の証拠) を緩めない
- 同じページに前の年度の資料が並ぶ所 (涌谷・利府・山元の R7 と R8、岩沼の 2025 と 2026、穴水の半年ごとの 2 組) は、年の印で今の期間のものを選ぶ。
  年の印の無いもの (寄居の、リンクの文字が空の古い Excel 2 本) は読まない
- 期間の書いていない常設の資料 (大衡・七ヶ宿・仙台の「令和7年7月1日」現在) は、年の印が無いので `undated`。規則として返す (日付では答えない。§9 の 7)
- 時の証拠が古い常設の規則 (豊島の PDF は 2023 年の作成) も、人が `version` の裁定で今も有効と確かめるまで答えない

### 3.4 コードがすること・LLM がすること

| | コード | LLM (DeepSeek-V4.1-Flash、`llm.py`) |
|---|---|---|
| 表の形・結合したマス | する (DOM の格子、PDF の罫線・矩形、画像の線) | しない (パイロットで見落とした)。行と列の数を答えさせて確かめに使うだけ |
| 本文の範囲・使い回しの部分 | する (§3.2) | しない |
| 年の印・時の証拠 | する (§3.3) | 年の印をもう 1 つの読みとして読む (どこにあるかも答えさせる) |
| しるし (斜体・`img` の title・「*」・「ー」) | 棚卸しして決まりの表に当てる (§3.6) | 生の HTML の断片を読み、しるしの意味を含めて答える |
| 見出し・凡例の文字 | 文字層があれば読む | 画像を読む (文字層があればもう 1 つの読み。無ければ 2 回、別の月のページや別の切り出しで) |
| 見出し → 品目 | 辞書で当てる | 当てる (もう 1 つの読み)。辞書に無い言い方 |
| 行 → 地区 | 地区の文法で読む | 同じマスの生の断片を読み、名前は資料のままで地区の中身を JSON にする (町字の一覧は渡さない。§3.9) |
| マスの数字 | 文字層を読む、または位置から日を計算する | 切り出した画像を読む |
| マスの品目 (色・印) | 塗りの色を凡例の色に当てる | 文字の札を読む。色だけのときは確かめ役 |
| 規則の文 | 規則の文法で読む | 生の断片から規則の JSON (`ambiguous_week` を選べる。§3.7) |
| 年末年始・祝日・期間・但し書きの文 | 本文の範囲の中の、日付と言い回しの正規表現 | 本文の範囲の全体を読んで、方針と但し書きを `span` つきで返す |
| 区分けの決め方・収集か持ち込みか | 列の見出しと言い回し | 同じ文から答える (島・村では両方必ず) |
| 比べる・確かめる・日付を作る | する | しない |

LLM に渡す文は資料の抜粋で、指示として扱わないと system の指示に書く (`judge.py` と同じ)。答えは JSON だけにさせ、
問いかけの版・モデル・入力の sha256 ごとに答えを覚えて、同じものは聞き直さない。

### 3.5 型ごとの読み方

**A. CSV・Excel** (荒川・杉並・世田谷・江東・日高の CSV、狭山・金沢・仙台 粗大の Excel)

- コード: 文字コードは、HTML と同じ 1 つの判定で決める (**BOM** → HTTP の charset → `meta charset` → UTF-8 として読めるか → cp932。どれでも読めなければ止める)。
  BOM を先に見るのは、杉並・日高・多摩の CSV が BOM つきの UTF-8 で、サーバーの charset の見出しが違っていても BOM のほうが確かだから。
  見出しと BOM がぶつかったことは `build` に記録する。
  cp932 は CSV (世田谷・江東・荒川) だけでなく、組合のサイトの HTML 6 ページ (az9.or.jp・hozenkumiai.or.jp) にもある。
  見出しの行は中身で探す: 「町名」「地区」「曜日」「品目」などの見出しの言葉を 2 つ以上含む最初の行 (世田谷の CSV は列の見出しの上に題の行がある)。
  Excel は結合したマス (仙台 粗大 483) を広げ、隠しシートと古い年度のシート (狭山の 2025 年の「柏原」) を外す
- LLM: 列の見出し → 品目・地区・規則の列の対応。行の見本 (先頭と無作為の 20 行ずつ) を読ませて、コードの読みと比べる
- 気をつけること: 日高の CSV は 2020 年度 (時の証拠で外れる)、江東の CSV は「隔週」だけで起点が無い (→ 広げない)、多摩の CSV は分け方のデータで日付が無い。
  荒川の CSV (番地の単位で 2,250 行、年末年始の備考の列つき) がいちばん良い形

**B. HTML の表** (金沢・小松・能美・登米・草加・塩竈の地区の一覧・七ヶ宿・新宿・北区・大田)

- コード: 表を 2 通りで読む。(1) 仕様どおりに rowspan・colspan を広げた格子 (`kz_calendar.grid` と同じ)、(2) 行ごとに頭のマスから順に読む。
  2 つが違えば壊れた表 (七ヶ宿) の疑いとして `structure` の裁定に回す。しるしを棚卸しする (§3.6)。リンクの文字「(PDF 791KB)」は地区のマスから外す (能美)。
  大田の横に 2 組並んだ広い表 (r12・r2c2 の結合) は格子を広げてから組に分ける
- 品目の見出しの中の規則の切れ端 (三郷「びん、かん（第1・3週）不有資（第2・4週）」の列のマスは曜日だけ) は、マスの文字の前に付けて読む。
  切れ端が 2 つ以上 (1 つの見出しに品目が 2 つ) なら、その列の規則は `multiple` (rule_unparsed)。マスの曜日だけを読んで毎週と言わない。
  「（月2回）」「（週1回）」(世田谷) は回数の書き添えで、規則の切れ端にしない
- 規則のマスの中の年末年始の文 (金沢の燃やすごみ「年末は12月28日（月曜日）まで 年始は1月4日（月曜日）から」、羽咋の可燃の群ごとの「12/29(火)最終で 1/5(火)から」) は、
  そのマスの地区・品目だけの `year_end` にする (ほかの地区・品目に広げない)
- LLM: 2 つ目の読みは、コードが取った文字ではなく、**タグと属性を残した表の生の HTML の断片** を読む (`script`・`style` を除く。長ければ行のまとまりで分け、見出しの行を毎回付ける)。
  見出し → 品目、地区のマス → 地区の中身、規則のマス → 規則、しるしの意味。日程の表かどうか (草加の配布場所の表、大衡の店の表を外す)
- 地区の定義がリンクのまわりにある所 (塩竈) は、`anchor_context` を同じように 2 つの読みで読む
- 鶴ヶ島のような 1 か月 1 ページの日ごとに変わるページは §5.7

**C. HTML の文** (川北町の「【可燃物（燃えるごみ）】 毎週 月曜日・木曜日」、七尾のテキスト版の日付の一覧、三宅村)

- コード: 見出し (【】・見出しの要素) で区切り、規則の文法 (§3.7) で読む。日付の一覧「4月21日,5月19日,6月9日…」はそのまま `listed`
- LLM: 同じ本文の範囲を読んで規則と地区を JSON にする。日の書いてある文ごとに、収集か持ち込みかを 2 つの読みの両方が決める
  (三宅「持込 月・水・金」が収集の日の間にある、川北「偶数月は、第２日曜日を土曜日の振替として開所」は粗大ごみの持ち込み)

**D. 文字の PDF: 罫線のある表** (仙台・大衡・色麻・女川の資源ごみの表、日高・川越・野々市の日付の表)

- コード: PyMuPDF の `find_tables` で表とマスを取る。結合したマスが空で返るので、罫線の位置から結合を決めて埋める (色麻・熊谷・小金井)。
  2 つ目のやり方として、罫線を自分で束ねた格子と比べる。仙台は 1 ページに 6 列の表が 2 つ並び、見出しが 23 回繰り返す (繰り返しの見出しを外す)
- 日付の表 (地区・コース × 品目 × 月 → 日の並び: 日高の令和8年度の日程表、川越、色麻、野々市) は、この型で `printed` にする
- 文字の対応が壊れた字 (日高のコース番号 10〜20 が U+2B31〜U+2B3B になる、美里の数字が「•‣․‥…‧」になる) は、コードの読みを「読めない」にし、
  LLM の画像の読みだけの値 (`single`) として裁定に回す。人が確かめたフォントごとの字の対応の表ができたら、それを使う。推し量りで字を当てない
- LLM: 見出し → 品目、地区のマスの文 (仙台の「あけぼの町6-2，6-10～6-17，7-25～7-53，7-55」)、規則の略記「1･3金」の意味 (仙台は資料に定義がある)

**E. 文字の PDF: 罫線の無い表** (七尾の区分表 = 塗りの矩形だけ、羽咋 = 横線だけ、寄居 = 何も無い)

- コード: 塗りの矩形を束ねてマスにする (七尾)。横線の間を 1 行とし、縦に真ん中にある曜日の見出しをその行に付ける (羽咋)。線も矩形も無ければ、
  文字の並び (x の位置で列、y の間で行) から組む (寄居)。折り返した名前をつなぐ (「は／まなす団地」)
- 2 つ目の読みは、ページの画像を LLM に読ませた行ごとの JSON

**F. 文字の PDF: 日付の月表** (大島町・国立・滑川・吉川・寄居・足立のカレンダー、女川の町民カレンダー)

- コード: PyMuPDF の `get_text("words")` (文字と位置) と `get_text("dict")` (文字の色) で読む。月の見出しと曜日の見出しで月のかたまりを見つけ、1〜31 の数字を日のマスの目印にする。札の文字 (「可燃」「缶」「ビン」) を、位置でいちばん近い日のマスに付ける。
  同じ位置に重なった文字は 1 つにする (国立・滑川)。白い文字・灰色の月の外の日を外す (足立)。品目が塗りの色だけなら、塗りの矩形の色を凡例の色に当てる
- 位置から日を計算する: 月と曜日の並びが分かれば、マスの行と列から日が決まる。印字の数字と合うかを確かめる (2 段の 24/31 のマスは別に扱う)
- LLM: 月のかたまりの画像 (120dpi 以上) に、コードが番号つきの枠を描いて渡し、枠ごとの日と札を読ませる。これが文字層の読みとは別の、2 つ目の読みになる
- 冊子 (町民カレンダー) は §5.2

**G. 輪郭線の PDF** (丸森・伊奈・毛呂山・葛飾 2026 など。発見の `pdf_image` の約半分)

- 文字が図形なので文字層は無い。`find_tables` は何も返さない (調べたすべての輪郭線のカレンダーで)。
  かわりに図形 (`page.get_drawings()`) から、同じ大きさの矩形の並び (丸森: 41×44pt のマス 540 個) や線の格子 (毛呂山: y 96 通り × x 66 通り) を束ねて、月のかたまりと日のマスを作る
- 日: 月の見出しと曜日の並びが分かれば、マスの位置から計算できる (数字を読まなくてよい)。月の見出しと凡例は LLM が 1 回読む (2 人で)
- 品目: マスの塗りや印の色を、凡例の色に当てる (Lab の色の距離)。凡例の文字は LLM が読む
- 2 つの読み: コード (位置からの日と色からの品目) と、LLM (番号つきの枠の画像から日と品目)。2 段のマス・斜めのマス・縞のマスは、位置からの日が 2 つになるので、LLM の読みと裁定で決める
- 同じ業者の型 (アドコーポレーションの丸森・山元・利府、毛呂山と鶴ヶ島の同じ仕事番号) は、構造の見つけ方を使い回す。ただし資料ごとに確かめる

**H. 画像の PDF** (涌谷・輪島・珠洲・富谷・大和・府中。スキャンか画像に変換したもの)

- コード (読み取り役 A): 200〜300dpi で描き (涌谷は 84 枚の画像のタイルなので 1 ページに組み直す)、長い横線と縦線 (画素の並びの投影) で格子を作る。
  月の見出しと曜日の並び (LLM が 1 回読み、2 人で確かめる) から、マスの日を位置で計算する。塗りの色の集まりを凡例の色に当てて品目を決める (G と同じ考え)。
  使うのは numpy (足りなければ OpenCV)
- LLM (読み取り役 B): 番号つきの枠を描いた月の画像で、日と品目を読む
- コードで格子が取れないもの (線が薄い・傾いたスキャン) だけ、LLM 2 つ (切り出し方 月ごと / 行ごと と問いかけ方を変える) にし、その一致は `agreed_weak` (§3.11)
- 72dpi (品川) のように読めないものは読まない (人か問い合わせ)

**I. 読めない所** (アプリだけ、ブロック、見つからない) は §5.5〜5.6。

**J. 自治体が公開している JavaScript の表示** (`js_view`。岡山市の kintone の公開ビューなど) は §5.5。

### 3.6 マークアップの棚卸し (しるし)

HTML では、意味が文字ではなく **しるし** (タグ・属性・記号) で書かれていることがある。初版では LLM もコードが取った文字を読んでいたので、
しるしは 2 つの読みの両方から同じように落ち、2 つの読みがそろって誤っていた (塩竈の斜体の町を町全体として答える、鶴ヶ島の空のマスを「収集なし」と読む)。

1. **棚卸し**: コードが表ごと (と `anchor_context` ごと) に、文字以外のしるしを数える:
   `em` `i` `strong` `b` `s` `del` `u` `sup` `sub`、`img` (alt・title)、style の色・背景色・取り消し線、class、
   記号 (`*` `※` `ー` `-` `―` `✕` `×` `○` `◎` `△` `★`)、空のマス
2. **決まりの表** (`markup_rules`): しるしの読み方は、資料の中の説明か、型ごとの決まりで決める。例:

   | しるし | 読み方 | 出どころ |
   |---|---|---|
   | 塩竈の `<em>` (斜体) | その町・番に `partial` (`split_known: false`) | ページの説明「斜体 = 番地により別の地区があります」 |
   | 鶴ヶ島の `img` の title・alt | マスの品目 (「2026年10月1日は燃やせるごみ（可燃ごみ）…の収集日です。」) | 型の決まり (title の文を品目の辞書に当てる) |
   | 大田の「ー」「-」だけのマス | その回は収集なし (`none`) | 型の決まり (§3.7 の「無し」) |
   | 新宿の「*」だけのマス | 清掃事務所に問い合わせ → その行は `rule_contact` | ページの説明 |
   | 能美のリンクの文字「(PDF 791KB)」 | 地区の文字から外す | 型の決まり |
   | 空のマス | 下の「空のマスの決まり」 | 資料の説明か型の決まり |

   作る順 5〜6 で足した型の決まり (案。人が確かめるまで版 @1 のまま。`blank_chome@1` のほかは、読みに使う値を増やすのではなく、意味の無いしるしを止める理由から外すもの (`calendar_link@1` は止める理由を足す)。`blank_chome@1` は空のマスを町名の丸ごとと読む、読みを足す決まりなので、人が確かめるまでは止める理由に残し (`markup_unhandled:blank`・`markup_unhandled:dash_chome`)、待ち行列 (`markup`) に入れる):
   `layout_style@1` (配置・大きさだけの style)、`layout_class@1` (xl65・center などの配置の class)、
   `uniform_emphasis@1` (太字・斜体が、列 (見出しは見出しの行) のすべてのマスの文字全体にかかる。世田谷のマスはすべて `<strong>`。一部のマスだけなら決まりの無いしるし)、
   `unused_column@1` (読みに使わない列 (出し方・主なもの・管轄) のしるし。その列の文字は §3.8 の洗い出しで見る)、
   `note_marker_emphasis@1` (注の印「（注）」だけの強調。渋谷「宇田川町<strong>（注）</strong>」。注の文は §3.8)、
   `blank_chome@1` (丁目の列の空のマスか「―」で、町名が上の行と違う → その町名の丸ごと。世田谷「砧公園」・渋谷「鶯谷町 ―」)、
   `calendar_link@1` (地区ごとのカレンダーへのリンク → その行は `pending_printed`)

   **空のマスの決まり**: 空のマスは、NFKC と空白 (ゼロ幅の空白を含む) を除いたあとで文字が無いマス。黙って「収集なし」とも「上と同じ」とも読まない。
   - マスの中に `img`・`svg`・`object`・`input`、style の色・背景色、同じ表のほかのマスと違う class・`title` 属性のどれかがあれば、空ではない。
     そのしるしとして棚卸しする (鶴ヶ島のマスは `img` の title にしか品目が無い)
   - 結合の取りこぼしを先に疑う: 2 通りの格子 (§3.5 B) のどちらかで、上か左のマスと結合していれば、その値で埋める (色麻は結合したマスが空で返る)。
     2 通りの格子で埋め方が違えば `structure` の裁定
   - それでも空のマスを `none` (その回・その品目は収集なし) と読んでよいのは、次のどちらかのときだけ。決まりは `markup_rules` に版つきで持つ:
     (a) 資料の凡例・説明が空欄の意味を書いている (「空欄の日は収集がありません」のような文)。
     (b) 型の決まりで、日付の月表の **日のマス** に品目の札を書く形 (型 F・G・H と、HTML の月表) で、同じ月表のほかの日のマスには札があるもの。
     地区 × 品目 × 月の表 (型 B・D の日付の表) の空のマスは (b) に入らない
   - どちらでもない空のマスがある表は `markup_unhandled:blank` で止め、待ち行列 (`markup`) で人が決める

3. **決まりの無いしるし** が 1 つでもある表は、その表から作った系列を answerable にしない (`blocked_by: markup_unhandled:<種類>`)。
   新しいしるしは待ち行列 (`markup`) に入れ、人が決まりの表に足す (足した決まりは版つきで残し、ほかの自治体にも使う)
4. 2 つ目の読み (LLM) には、生の HTML の断片を渡し、しるしの意味も答えさせる (§3.5 B)。コードの決まりの表の読みと比べる。
   描いた画面の画像 (番号つきの枠) を渡すやり方は、M2 以降に試す

### 3.7 規則の文法

コードの文法が読み取り役 A、LLM が B。どちらも次の中間の形 (IR) にしてから比べる。

| 資料の言い方 | IR | 日付にするとき |
|---|---|---|
| 毎週 月曜日・木曜日 / 月・木 | `{"kind": "weekly", "weekdays": ["MO", "TH"]}` | そのまま |
| 毎週 月曜日（1回目の月曜日を除く） | `{"kind": "weekly", "weekdays": ["MO"], "except_nth": [1]}` | 月の何回目かで抜く (石狩)。月の回を数えるので、§2.5 の 4 では月ごとの規則として扱う (窓 W・休みの月) |
| 第1・第3水曜日 / 第１・３水 / 1･3水 / 1回目と3回目の水曜 / 第二・四水 | `{"kind": "monthly_nth", "weekday": "WE", "nth": [1, 3]}` | 月の何回目か = `(日 - 1) // 7 + 1`。RRULE `BYDAY=1WE,3WE` |
| 第１・３・(5)火 / 第2・4・5水 | `nth: [1, 3, 5]` | 5 回目が無い月は無し |
| 5番目の曜日は収集なし (品目ごと) | 規則に `except_nth: [5]` を付ける | 新宿 (金属・陶器・ガラス)。どの品目に当たるかは `span` の節で決める |
| 最終金曜日 / 月末の金曜 | `{"kind": "monthly_last", "weekday": "FR"}` | `BYDAY=-1FR` |
| 第1週・第3週 / 1・3週目 / 第2、4週 | `{"kind": "ambiguous_week", "weekday": "SA", "weeks": [1, 3]}` | 広げない。下の決まり |
| (資料が暦の行で数えると決めているとき) | `{"kind": "calendar_week", "weekday": "SA", "weeks": [1, 3], "week_starts": "SU"}` | 暦の行で数える |
| 隔週水曜日 | `{"kind": "biweekly", "weekday": "WE", "anchor": null}` | 起点 (`anchor`) が同じ期間の資料の日付から決まるときだけ |
| 3週間に1回の月曜日 | `{"kind": "cycle", "weekday": "MO", "every_weeks": 3, "anchor": "2026-04-20"}` | 同上 (七尾はテキスト版の日付の一覧が正) |
| 毎月10日・25日 | `{"kind": "monthly_day", "days": [10, 25]}` | 休みの日に当たったときの扱いが要る。§2.5 の 4 では月ごとの規則 |
| 6・9・12・3月の第4木曜日 | `{"kind": "months", "months": [6, 9, 12, 3], "rule": {"kind": "monthly_nth", …}}` | |
| 5〜10月のみ第1水曜日でも出せる (足す) | `{"kind": "months", "months": [5, 6, 7, 8, 9, 10], "rule": {…}, "adds_to": "c7"}` | 東秩父のペットボトル。足す規則は、それだけを系列の規則として広げない (`rule_unparsed`)。足す言い方は文の終わりの決まった形だけで、後ろの文字 (「…でも出せますが、8月は休み」「（雨天中止）」) は消さずに `rest` へ |
| 5月〜9月は隔週 | `{"kind": "seasonal", "from": "05-01", "to": "09-30", "rule": …}` | 起点が要る |
| 4月15日～9月15日は毎週月曜日 | `{"kind": "seasonal", "from": "04-15", "to": "09-15", "rule": …}` | 日まで書いてあれば日を枠の端にする (月まるごとにしない)。月に無い日は読まない |
| 4回に1回は小型家電の日 | `{"kind": "subcycle", "of": <規則>, "every": 4, "anchor": …}` | 起点が要る |
| 随時・申し込み | `{"kind": "on_demand"}` | 日付にしない (`mode` は `dropoff`・`reservation`) |

**「第N週」(`ambiguous_week`) の決まり**:

- 「週」を含む規則の言い方 (第N週・N週目・第N、M週) は、資料がどこかで意味を決めていなければ `ambiguous_week` にする。
  読みは 3 通りある: 月の何回目 (`monthly_nth`)、日曜始まりの暦の行、月曜始まりの暦の行。曜日によっては毎年いくつかの月でずれる
- 資料が決めていれば従う: 「当該月の第1回目」(滝川・南幌・紋別)・仙台の「その月の1回目と3回目」→ `monthly_nth`。暦の行と書いてあれば `calendar_week` (週の始まりの曜日も)
- 印字の日付があれば 3 通りをすべて広げ、印字と合う読みが 1 つだけならそれを採る (2 つ以上が全部の日で同じなら、どれでもよい。日曜始まりの暦の行の土曜は月の何回目と同じになる。八潮)。
  合う読みが無いか、印字が無ければ `rule_ambiguous` で種類 3
- LLM の答えの形にも `ambiguous_week` を入れ、「決められないときは ambiguous_week」と指示する (IR の形に引っぱられて `monthly_nth` を選ばないように)

**起点**: `biweekly`・`cycle`・`subcycle`・`seasonal` の `anchor` は、同じ期間 (`period_id`) の資料の日付からだけ取り、その期間の中の日であること。前の年度の資料の日付から取らない。

**文字の前処理** (規則の文法の中だけ): NFKC、全角数字、「･」「・」「、」「，」、「曜日」「曜」の省略、「第」の省略 (「2･4水」)、
漢数字 (「第二・四」) とカタカナの「ニ」(「第ニ」) を数字にする。「ニ」を数字にしてよいのは「第」と区切りの間だけで、2 通りに読める寄せ方になったら止める (結果を出さない)。
地名の中の「ニ」(小松「向本折第ニ」、鶴ヶ島「脚折町ニ～六丁目」) は地区の文法の側で、address-normalize の `fold` として扱う (§3.9)。

**「無し」のしるし**: 日付・規則のマスの文字が、NFKC と空白の除去のあとで「ー」(U+30FC)・「-」・「―」・「‐」・「−」・「✕」・「×」だけなら `none` (その回は収集なし) にする (大田の 1 月)。
NFKC ではこれらは 1 つにならないので、この表で寄せる。ほかの文字と混ざっているときは、§3.6 の棚卸しに回す。

- 読めなかった文は IR にせず、文のまま `rule.text` に残す (`rule_unparsed`、答えの種類 3 で返す)

### 3.8 但し書きの洗い出し

初版は §2.5 の条件を「4 つのことが書いてあるか」だけで見ていたので、表の外の但し書きが使われずに落ちても気づけなかった。
LLM もコードが選んだ抜粋しか見ないので、コードが落とした但し書きは LLM も落とす。

1. **原文の場所**: IR・例外・方針・地区の中身は、どれも使った原文の `span` を持つ (§2.7)
2. **印で洗う**: 本文の範囲 (§3.2) を、但し書きの印で洗う (NFKC のあとで探す):
   - 数え方: 「第5」「5番目」「5回目」「5週」「番目」「回目」「当該月」「隔週」「月末」
   - 範囲・除外: 「除く」「以外」「のみ」「だけ」「N月～N月」「N月から」「夏」「冬」
   - 休み・変更: 「休み」「お休み」「休止」「中止」「祝」「祭日」「振替」「臨時」「変更」「変わ」「順延」「天候」「通常どおり」「通常通り」
   - **否定の言い方**: 「ありません」「しません」「行いません」「行わない」「なし」「無し」
   - **期間の名前**: 「年末」「年始」「正月」「お盆」「盆休み」「連休」
   - 記号: 「※」「注」「*」
   否定の言い方と期間の名前を入れたのは、国立「12月31日のごみ収集はありません」、美里「1月1日（金）は収集しません」、
   日高「…施設の定期点検のため可燃ごみの収集は行いません」、鶴ヶ島「12月29日から1月3日の収集はありません」が、ほかの印を 1 つも含まないため。
   コードと LLM の両方がこの文を読み落とすと、規則から作った 12/31・1/1 が残ってしまう
3. **使われなかった但し書き**: 印を含む文 (か表のマス) のうち、どの `span` にも入っていないもの。LLM にも本文の範囲の全体から但し書きを挙げさせ、2 つの読みの和を取る
4. **止める** (日付の出どころによらず、1 つの決まり): 使われなかった但し書きは、当たりうる品目 (同じ表・同じ節の品目。節の外なら、すべての品目) の系列を、
   印字・一覧・規則のどれから作った日付でも答えにしない (`blocked_by: unconsumed_qualifier:<id>`)。
   但し書きが月を名指ししている (「5〜10月のみ」「6・9・12・3月」) ときだけは、系列ごと止めるかわりに、その月を `unknown_ranges` (`reason: unconsumed_qualifier`) にしてよい。
   期間の名前も月に数える (年末 → 12 月、年始・正月 → 1 月、年末年始 → 12・1 月、お盆 → 7・8 月。三鷹「※年末及び1月は…」は 12・1 月)。
   月の決まらない期間の名前 (連休・祭り) や季節 (夏・冬) があれば、月を名指ししていないとみなして系列ごと止める。
   理由: 但し書きは印字の日付も増やしたり減らしたりする。東秩父「※ペットボトルは5・6・7・8・9・10月のみ第1水曜日でも出せる」は、
   印字のカレンダーに無い日 (5〜10 月の第1水曜日のペットボトル) を足しうるので、印字だけを答えると、その日を「収集なし」と言ってしまう。
   待ち行列 (`qualifier`) で人が「意味が無い」(例: 広告の「※」)、「この IR・例外で使う」、「印字にもう入っている」と決めると、決まりとして残り (資料の sha256 つき)、止めが外れる
5. **使ったことにする関門 (`consume.py`。default-deny)**: 文・かっこ書き・マスの注と読み残し・名前のマスの文字・回数の書き添えを「使った」と
   数えるのは `consume.take` を通ったものだけ。通すのは、読み取り (祝日の扱い・年末年始・大型連休・第5週・deferred と caveat・月の名指し・
   かっこ書き・マスの注・名前のマス・回数) が値を返し、**文の全体が名前のある閉じた見本にまるごと当たった**ときだけで、その見本の名前を
   例外の `template` に書く。見本の外の文は値にせず、使われなかった但し書きとして止める (印を探す書き方・使った文の行のかっこ書きを
   まとめて使う書き方では、「ゴールデンウィーク中も収集しません」「祝日も収集します。（第5月曜日は休み）」「8月14日は休み、ほかの日も
   変更になる場合があります」の確かな部分が値にならずに消えた)。deferred・caveat の例外は止める向きなのでいつも作るが、文を使うのは
   「閉じた主題 + 含みの句」(主題に日付・休み・打ち消し・第N が無い) のときだけ。年末年始の文は、日付の範囲ごとに自分の述語を持ち、
   文の全体を読んだときだけ。読み取りが値を返したのに使えなかった文 (見本の外・品目の決まらない文 (`value_scope` の AMBIGUOUS)・
   行の折り返しの続きのある文) と、日付・期間の名前と収集の言葉を持つ文・行の折り返しの続き (「できません。」) は、但し書きの印が
   無くても但し書きにする。品目を決める見出しは、いちばん上のほかは品目の見出しか閉じた並びの一般の見出しだけ (地名だけの見出し
   「厚田区」「東町」の節の文は AMBIGUOUS)。「ただし」「なお」で始まり同じ行に主語の無い文も AMBIGUOUS。
   同じ系列に当たる年末年始の休みの期間が 2 つあって違えば `year_end_conflict` で止める
6. **外すのは文そのものが使われたときだけ (関門の回り道を閉じる)**: 洗い出しから外してよいのは、その文 (`Sentence`) そのものが関門を
   通って使われ (`consumed`)、使えなかった印 (`unconsumed_reading`) が無いとき (`consume.used`)、名前のマスの文、読み切った規則のマス
   (要素の同一性。見出しの行の列の札だけのマス「地区」も) と型 C の規則・日付の一覧の行 (行と行の中の位置) の中の文だけ。
   文字の一致・部分の一致では外さない (表のマスの「休み」が、ほかのマスの「（祝日は休み）」の文字の一部だから外れた。
   品目の節で使った「祝日は収集しません。」と同じ文字の、地名の節の文が外れた)。B (LLM) の但し書きも、A の使った文と但し書きの文で
   読み切れていなければ (`compare.span_covered`。文字の一部が同じだけでは読み切れていない) B だけの但し書きにする。
   日程の節 (`policy_eligible` の文。見出しは除く) の、どの読み取りも使わなかった文は、印が無くても、地区・場所・曜日・前後の日
   (翌日・前日・その日・翌週)・日付を言うか、続きの言葉 (が、・けれど・ただし・なお・また) で始まれば但し書きにする
   (「ただし、東町は翌日に収集します。」「東町の燃やすごみは火曜日と金曜日です。」)。文の続きは、同じ行だけでなく同じ塊の次の行
   (PDF の見た目の行・同じ親の続けて並んだ `<p>`・`<li>`) も見る (「祝日も収集します」の行の次の段落が「が、東町は翌日になります。」なら、
   前の文を使わない)。日付の一覧 (型 C の listed) は、規則の頭から続く日付の並びだけを読み、並びの後ろ (「※7月13日は収集しません」
   「（8月は休みです）」) は規則のマスの読み残しと同じく `cell_notes` と関門に通す。休みの理由の句は閉じた並び (施設の点検・工事・
   祭典・年末年始など。地名・施設の名前のある「東町の道路工事のため」は見本の外)。別の文の「年末は…まで」「年始は…から」は、
   1 つの文の見本と同じく前後が逆でなく間が 40 日までのときだけ組にする

例:

| 但し書き | どう使うか |
|---|---|
| 新宿「月の「5番目の曜日」に収集はありません」(表の外) | 金属・陶器・ガラスの規則の `except_nth: [5]` が使う |
| 石狩「毎週 月曜日（1回目の月曜日を除く）」 | `weekly` + `except_nth: [1]` が使う |
| 東秩父「※ペットボトルは5・6・7・8・9・10月のみ第1水曜日でも出せる」 | `months` つきの足す規則が使う |
| 能美「注：松が岡 第2・第4木曜日」 | 地区を分ける `inline` が使う |
| 赤平「第5週がある月の水曜日、土曜日の収集は休み」 | IR に無い形 (「第5週がある月」が月全体か第5週だけか決まらない)。使われない → 水・土の品目は、印字があっても答えない |
| マスの中の「（祝日の収集は休み）」 | その品目の `holiday_policy` (`not_collected`) が使う。月ごとの規則なら、祝日で回が消える月は §2.5 の 4 (D) で不明 |
| 国立「12月31日のごみ収集はありません」(冊子のマス)、美里「1月1日（金）は収集しません」 | `year_end` (`skip`) が使う |
| 日高「５月４日(月)、12月31日(木)は、施設の定期点検のため可燃ごみの収集は行いません」 | 可燃の `cancelled` が使う (日高の日程表は印字なので、確かめ §4.1 の 5 に使う) |
| 渋谷「（年末年始は変更あり）」 | 不燃ごみの `deferred` が使う (§2.6 の見分け方) |

### 3.9 地区の文法

| 資料の言い方 | 読んだ結果 |
|---|---|
| 赤井町・西任田町・五間堂町 | 町字 3 つ (`machiaza`、丸ごと) |
| 青柳1から8丁目 / 江北１～５、７丁目 | 丁目を広げる |
| 旭町1から3丁目（旭町団地を除く） | 丁目 3 つ、条件 `facility` (旭町団地、`negate`) |
| あけぼの町6-2，6-10～6-17 / あけぼの町（上記以外） | `block_range` と、同じ町の `remainder` (「上記以外」はほかの行より後に当てる) |
| 5-13，5-25～5-末 | `range` (「末」は `"end"`) |
| 松が岡五丁目133-3～21,177～ | `range` の終わりの無いもの (`{"from": "177", "to": null}`) |
| 粕壁(1〜4丁目を除く) / 新方袋(飛地を除く) | `except` / `enclave`。飛地は図形が要る (`needs_line` と同じ扱い) |
| 千里浜町（大宮、白山、宇賀…） | 町字 1 つ。かっこの中は `note` (地区を分けない) |
| 下牧（11班・12班以外） / 橘１班 | `community` と `han` |
| 石堂５～８番、石堂９番一部≪石堂第二町内会≫ | `block_range`、`partial`、`note` (町内会の名前) |
| 斜体の 新富町 (塩竈) | `partial` (`split_known: false`) → 町全体を聞き返す |
| 谷塚町（国道4号バイパスの東側・県道川口草加線の北側） | `line_side` |
| 金山・大内・小斎 (旧村) | `former_municipality` |

- LLM には **町字の一覧を渡さない**。資料の名前をそのまま (`name_verbatim`) と、条件の正規形 (§2.3) だけを返させる。
  理由: 一覧を渡すと、古い町名や収集のための名前を今の町字に寄せてしまい (金沢の旧町名の行 46、東松島「この表で使用している収集区域の表記は、ごみ収集用です」、
  カタカナの「ニ」)、2 つの読みが同じ寄せ方でそろう
- 町字への当て方は address-normalize だけで行い、当たり方 (`exact` / `fold` / `ambiguous` / `none`) を `members[].match` に持つ。
  `fold` でしか当たらないもの、2 つ以上に当たるもの、当たらないものは待ち行列 (`members`) に入れ、裁定まで `unresolved`
- 2 つの読みの比べは、(単位, 資料の名前の正規化, 条件の正規形の集まり) で行う。言い回しの違い (「1から3丁目」と「1～3丁目」、「以外」と「を除く」) では食い違いにしない。
  理由: 自由な文の条件を文字で比べると、言い回しだけで食い違いが山のように出る (新宿 81 行・北区 30 行の「以外」「を除く」)

### 3.10 LLM の仕事 (問いかけと答えの形)

| 仕事 | 渡すもの | 答え (JSON) |
|---|---|---|
| ページの型 | 縮小画像 (長い辺 800px) と文字の抜粋 | `{"page_type", "fiscal_year", "year_token_where", "is_current_version", "notes"}` |
| 見出し・凡例 | コードが切り出した見出しの行・凡例の画像 | `{"cells": [{"col": 1, "text": "…"}], "legend": [{"swatch": 1, "text": "…"}], "unsure": "…"}` |
| 見出し → 品目 | 公式の名前の一覧、分類の鍵の一覧、分け方のページの抜粋 | `{"label": "…", "coarse": ["…"], "mode": "curbside", "why": "…"}` |
| 行 → 地区 | 地区のマスの生の HTML 断片 (タグ・属性つき) か、PDF の行の文字。町字の一覧は渡さない | `{"members": [{"name_verbatim", "unit", "conditions": [<正規形>], "markup": ["em"]}]}` |
| マスの数字と札 | 番号つきの枠を描いた月の画像 (120dpi 以上)、月と曜日の並び、凡例 | `{"cells": {"<枠の番号>": {"days": [24, 31], "labels": ["可燃"]}}, "unsure": "…"}` |
| 規則の文 | 規則のマス・文の生の断片 | 規則の IR のリスト (§3.7。`ambiguous_week` を含む)。どれにも `span` |
| 方針と但し書き | 本文の範囲の全体 (見出しの道すじつき) | `{"holiday_policy": {"value", "covers", "shift", "span"}, "year_end": [{"category", "treatment", "dates", "others", "span"}], "deferred": [{"period", "dates", "span"}], "caveats": [{"span"}], "closures": [{"dates", "category", "span"}], "contingency": [...], "qualifiers": [{"text", "span", "applies_to"}], "ignored_office_hours": [...], "valid": {...}}` |
| 区分けの決め方 | 列の見出しと注意の文 | `{"basis", "span"}` (`basis` は `residence` / `collection_point` / `unknown`) |
| 収集か持ち込みか | 日の書いてある文 | `{"mode", "span"}` (島・村では必ず) |
| しるしの意味 | 表の生の HTML 断片と、ページの説明の文 | `{"markup": [{"kind": "em", "meaning": "partial", "span"}]}` |

- 表の形 (行・列・結合したマス) は、確かめ済みのものを文で渡す。パイロット §6 では、形を渡すと 324 マス中 323・324 が正しく、渡さないと列を取り違えた
- 1 回に読ませる量は、月のかたまり 1 つまで (女川: 1 回 入力 約1.7千・出力 約2.2千トークン)。本文の範囲は 1 回 1 万字まで
- 「読めない・はっきりしない所は空にして `unsure` に書く」「決められない規則は `ambiguous_week` か文のまま」と指示する。推し量りで埋めさせない。
  `year_end` の `others` (ほかの回の数え方) は「文がそう言っているときだけ。言っていなければ null」と指示する (羽咋の振り替えの文から推し量らせない)

### 3.11 2 つの読みと比べ方

| 値 | 読み取り役 A | 読み取り役 B |
|---|---|---|
| 表の形 | コードのやり方 1 (DOM の格子 / `find_tables`) | コードのやり方 2 (行ごと / 罫線・矩形を自分で束ねる)。LLM には行と列の数だけ答えさせる |
| マスの日 (文字層あり) | コード (文字層) | LLM (番号つきの枠の画像) |
| マスの日 (輪郭線) | コード (位置から計算) | LLM (番号つきの枠の画像) |
| マスの日 (画像) | コード (画像の格子の位置から計算) | LLM (番号つきの枠の画像)。格子が取れないときだけ LLM 2 つ (`agreed_weak`) |
| マスの品目 | コード (色 → 凡例、または文字層の札、`img` の title) | LLM |
| 規則・地区・期間・方針 | コードの文法 | LLM (生の断片・本文の範囲の全体) |
| しるし | コードの決まりの表 | LLM (生の断片) |
| 見出し → 品目 | コードの辞書 | LLM |

独立の度合い (`independence`):

| 組み合わせ | 一致の扱い |
|---|---|
| コードと LLM | `agreed` |
| 別のモデルの LLM 2 つ | `agreed` |
| 同じモデルの LLM 2 つ (問いかけ・切り出しだけ違う) | `agreed_weak` (答えてよいが、監査の抜き取りを 5 倍。§4.5) |
| コードの 2 つのやり方 | 表の形にだけ使う |

- 比べる前にそろえる: 文字は NFKC と空白の除去、日付は (地区, 品目, 月) ごとの日の集まり、地区は (単位, 正規化した名前, 条件の正規形の集まり)、規則は IR、方針は (値, `span`)
- 結果は 1 つずつ `agreed` / `agreed_weak` / `disputed` / `single` / `both_unsure`。`agreed`・`agreed_weak` 以外は裁定に回す
- 同じ資料を 2 つの形式で出している所は、資料どうしも比べる (金沢の HTML と Excel `2026tikubetsu.xls`、草加の HTML の規則と PDF の日付、新座の HTML の日付と画像の PDF、鶴ヶ島の月ごとの HTML と画像の PDF)

### 3.12 裁定の待ち行列

```json
{"item_id": "172073:fy2026:schedule:172073-shigen-5:c2:2027-01",
 "kind": "cell",       // structure / cell / label / category / members / rule / policy / mode / version / rule_vs_printed / markup / qualifier
 "readings": {"A": {"reader": "code.pdf_bands@1", "value": [...]}, "B": {"reader": "llm.cells.B@1", "value": [...]}},
 "evidence": {"source_id": "s1", "page": 1, "bbox": [...], "crop": "data/readers/172073/crops/….png",
              "wide_crop": "data/readers/172073/crops/…_wide.png"},
 "priority": 0.8,      // 当たる人口 × 当たる日の数
 "status": "open"}
```

kind ごとの行き先:

| kind | 1 番目 | 2 番目 |
|---|---|---|
| `structure` (表の形・結合したマス) | コードのやり方 3 (PDF は描いた画像の線の投影、HTML は描いた画面の格子)。ほかの 2 つのどちらかと一致すれば採る | 人。LLM の票では決めない (パイロットで LLM は結合したマスを見落とした) |
| `cell` `label` `category` `members` `rule` `policy` `mode` | 強いモデル (Claude Opus 5.5)。2 つの読みを見せず、読み取り役より広い切り出し (月のかたまり全体と凡例と前後の行。表なら前後 3 行と見出し) を読ませる。どちらかと一致すれば `adjudicated` | 人 |
| `version` `rule_vs_printed` `markup` `qualifier`、`policy` のうち推し量りを認めるもの (`others`、§2.10 の羽咋) と `deferred` を `caveat` に下げるもの | 人 (決まりを足す仕事なので。強いモデルの票では決めない) | 自治体への問い合わせ |

1. 強いモデルに広い切り出しを渡すのは、切り出しが間違っていたとき (隣の月・隣の行が入っていない) に、3 つとも同じように誤るのを避けるため。
   女川の同じ部分を読むのに、Flash は 48 回で $0.15、Opus は $8.64 かかった (計画 §6)。これを 48 で割って画像の 1 件 約 $0.2 と見込む (広い切り出しで $0.3 まで)
2. それでも決まらなければ **人** (firemio) が資料を見て決める。理由を `note` に書く
3. 資料だけでは決まらない (地図だけ・自治会の範囲・画像が粗い) なら **自治体への問い合わせ** の待ち行列に入れ、それまでは答えない
4. 優先は人口の多い所、日付の多いもの (列の取り違えは 1 年分がずれる) から
5. 人の裁定は記録 (`data/readers/adjudications/`) に残し、同じ資料の sha256 なら使い回す。回帰に使うもの (金沢の `rule_vs_printed`) は `eval/fixtures/` に写して git に入れる

- **人の手間** (確かさ低。M1 で新宿・北区・仙台の行あたりの食い違いの率と 1 件の時間を測って直す)。初版の見込み (50〜180 時間) は裁定を 1 自治体 3 件と置いていたが、
  地区の行の食い違いは行の数に比例する (新宿は 171 行のうち 81 行が番地で分かれ、「上記を除く」26・「一部」11。北区は「以外」30。仙台は 865 行のうち 314 行。小松の町内会 251、涌谷の名前 80)。
  そこで 1 自治体あたりではなく、食い違い 1 件あたりで見積もる:

| 仕事 | 件数の見込み | 1 件 | 時間 |
|---|---|---|---|
| 地区の行の食い違いで、強いモデルで決まらないもの | 1,000〜5,000 (全国の地区の行 6万〜10万、条件つきの行の食い違い 5〜10%、その 3〜5 割) | 2 分 | 35〜170 時間 |
| 表の形の食い違い (人だけ) | 350〜900 (1 自治体 0.2〜0.5) | 10 分 | 60〜150 時間 |
| 規則と印字の違い (`rule_vs_printed`。品目 × 月のまとまり) | 600〜2,000 | 3 分 | 30〜100 時間 |
| 版・しるし・但し書きの決まりを足す | 500〜1,000 | 5 分 | 40〜80 時間 |
| 公開の前の監査 (300 系列 × 関門の単位 10。§4.4) | 3,000 系列 | 3〜5 分 | 150〜250 時間 |
| 計 | | | **300〜750 時間** |

- ほかに、公開のあとの監査が月 7〜10 時間 (§4.5) と、自治体への問い合わせがある。費用より人の手間が進み方を決める
- 毎年の更新: 見張り (§5.8) で中身が変わった自治体だけを読み直す。表の型が同じなら構造の見つけ方を使い回せるので、1 回目より安い。人の決まり (しるし・但し書き) も使い回す

### 4.2 japan-gomi-data との比べ

[japan-gomi-data](https://github.com/tecolicom/japan-gomi-data) (tecolicom、CC BY 4.0) には、38 自治体・976 コースの収集データがある
(固定したコミット `d786a985569efcf747adce721578a819d79ae891`、2026-10-05)。使うときは出典を書く。
石川・宮城 (パイロットの県) は入っていない。

- 使える度合い: A 17 (その自治体が読んだ資料そのものがキャッシュにある。埼玉 10・東京 7。2026 年度の日付のマス 約7.6万)、
  B 4 (所沢・江東・練馬・倉敷。資料へのリンクだけある)、C 12 (組合のサイト・オープンデータ・kViewer など、こちらが別の資料を読む)、D 5 (まだ取得していない)
- 比べる形: 地区 → 品目 → 2026 年度の日付。向こうの規則 (`weekly`・`monthly_nth`・`monthly_specific`・`overrides`・`unknown_periods`) を広げて作る。
  広げ方は向こうの公開の JSON と 8 コースで 1 日も違わないことを確かめた (調査で作った変換。§8 の `eval/jgd.py` に移す)。
  向こうの `cancelled` はその日の全品目を消し、休みでない `overrides` はその日の月ごとの品目を消す (三鷹・飯能の 1 月の 1 週ずらし)
- 測るもの:
  - **系列** (いちばん大事): 答えるとした系列 (`answerable: true`。関門を開ける前の確かめなので `published` ではなく `answerable` で数える。
    地区 × 品目のまとまり × 期間) ごとに、1 年分の日付が全部合うか。1 日でも違えば、その系列は誤り
  - **A. 日付のマス** (読み取りだけ): コース × 日 × 品目のまとまり の適合率・再現率・F1、`day_exact`、`series_exact`。
    年末年始 (12/26〜1/7)・祝日・29 日以降・毎週の品目と月ごとの品目に分けて出す
  - **B. 場所ごとの日** (住む人が見る答え): 向こうの地区 (町字) を、こちらの地区に当てて日付を比べる
  - **C. 地区の当て方**: 向こうの地区がこちらのどこかの地区にあるか、正しい地区に入ったか、2 つ以上に当たったか
- 品目の粒の違い: 向こうの品目のうち、どのコースでも同じ日のもの (びん+かん など) は 1 つのまとまりにして比べる (こちらの「びん・缶」を誤りにしない)
- 比べない日: 向こうの `unknown_periods`、期間の外。こちらの `unknown_ranges`・答えない系列は「答えなかった」として別に数える (誤りにも正しいにも数えない)
- 向こうの弱い所: 岡山の年末年始は過去の年からの推定、世田谷の 12 月は曜日の見直しの前、東秩父村は年末年始の記載が無い。
  食い違いを `gt_stale` (正解が古い) として分けてよいのは、向こうの `extracted_at`・`edition_ja` とこちらの資料の sha256・版の証拠が違うことを示せるときだけ。示せなければ誤りに数える
- 正解の側も規則を広げたものが多いので、`expanded` の比べは、規則・方針の読みの確かめにはなるが、規則の意味 (第N週など) の確かめとしては弱い。
  `expanded` は、印字のカレンダーがある所 (金沢・草加) で印字と比べるのを優先する
- 出し方: 見出しは **答えるとした系列の誤りの数 (0 であること) と、その 95% の上限 (誤り 0 なら 3/n)**。マスの単位の率は、列の取り違えのように 1 か所の誤りが 1 年分に広がる誤りを薄めるので、見出しにしない。
  資料の型 (§3.5 の A〜J) ごと・使える度合いごとにも出す
- tier A の 17 はほとんどが型 A〜F で、型 G・H の正解は無い。G・H は §4.5 の人の監査だけで測る

### 4.4 公開してよい条件 (答えの種類 1 にする条件)

次の 1〜7 がすべてそろった系列だけを `published: true` にする (§2.5)。答えの種類 1・2 (§2.9)、パック、台帳の人口の割合は `published` だけを使う。
`answerable: true` でも 5 の関門が開いていない系列は、`out/schedules/` に日付を持ったまま `published: false` で、種類 3 として返す。

1. 系列のすべての値が `agreed`・`agreed_weak`・`adjudicated` で、`blocked_by` が空
2. §4.1 の確かめのうち、その系列に当てはまるものに落ちたものが無い (落ちたものは、例外の原文で説明がついて記録してある)
3. 版の証拠がそろい (§3.3)、有効期間に今日が入る (か、これから始まる)。見張りに、同じ期間の新しい版の印が出ていない
4. 出典を見張りに入れた (中身の sha256 と、案内のページのリンクの集まり。§5.8)
5. **関門の単位が開いている**。単位は、資料の型 (§3.5 の A〜H と J の 9 つ) と、規則から作った日付 (`expanded`) の 1 つ、あわせて 10。
   単位ごとに、確かめた系列が 300 以上あり、誤り 0 (95% の上限 3/300 = 1%)。確かめは、japan-gomi-data の正解との比べ (§4.2) と、人の監査 (§4.5 と同じやり方) を足したもの。
   型 G・H は正解が無いので人の監査だけ。`gt_stale` は証拠のあるものだけ除く。
   誤りが 1 つでも出たら、その単位の関門を閉じ、同じ原因が当たりうる系列 (同じ読み取りの道具・同じ型の資料) を止め、原因を直して新しく 300 系列を確かめるまで開かない。
   系列の単位は `gate.unit` に書く (`expanded` の系列は `expanded`、印字・一覧の系列は資料の型)。閉じたら、その単位の系列の `published` をすべて false に戻す
6. 金沢・女川の回帰 (§4.3) が通る
7. 区分けの `basis` が `collection_point`・`unknown` なら境目の見張り (§2.9)、島なら島の証拠 (§5.4) がある

初版の関門 (japan-gomi-data の A の 17 自治体でマスの「一致したのに誤り」0.1% 以下) は、17 自治体が埼玉・東京だけで型 A〜F に寄り、
誤りが系列ごとにまとまって出る (1 か所の列・凡例の取り違えで 1 年分) のに、マスの率で薄めていた。

### 4.5 公開したあとの監査

- **抜き取る**: 公開している系列から、毎月 (と各段の終わりに) 抜き取る。層は 関門の単位 × 人口の大きさ。`agreed_weak` を含む系列は 5 倍の重みで抜く
- **系列の監査**: 人が資料 (印字・規則の文・方針の文) と、出力の 1 年分の日付を並べて見る。1 系列 3〜5 分
- **日の監査 (多めに抜く日)**: 12/15〜1/31 の日、第5週の日、祝日・振替休日・国民の休日、月の 29 日以降。これらの日だけを、系列をまたいで 1 回 100 日抜いて資料と照らす
- **数**: 公開の前は単位ごとに 300 系列 (§4.4 の 5)。公開のあとは毎月 系列 100・日 100 (月 7〜10 時間)
- **記録と公開**: 監査の 1 件ずつの記録は `data/readers/audit/` (git に入れない)。単位ごとの「確かめた系列の数・誤りの数・95% の上限」を
  `out/schedules/summary.csv` と台帳の `coverage.quality` に書いて公開する。誤りが見つかれば §4.4 の 5 のとおり関門を閉じる

## 5. 特別な場合

### 5.1 地区ごとの PDF

加須市 (69 本、1 本 約16.7MB、あわせて約1.15GB)、草加市 (20)、足立区 (99)、瑞穂町 (10 本、約7MB)、大島町 (地区ごと)、能美市 (行ごと)。

- 発見の上限 (`--max-docs 25`) で多くを取っていないので、段 0 で取る。段 0 の上限は 1 自治体 120 本・1GB。
  ただし **1 つのホストに同じ形で並ぶ地区ごとの資料の組** (同じ案内のページから、同じ形のファイル名・リンクの文字で並ぶもの) は、本数とバイトの上限の外にする
  (礼儀の 1 ホスト 1 秒 1 回・名乗る User-Agent・キャッシュは同じ。加須は 69 本で、間を空けるだけなら 70 秒ほどと転送の時間)。初版の 1GB の上限は加須を超えていた
- それでも取れなかった地区の資料 (ブロック・時間切れ) は、その地区を `blocked_by: ["doc_not_fetched"]` で出力に残す。黙って落とさない (§4.1 の 19)
- 地区の名前は、`anchor_text`・`anchor_context` と資料の見出しの両方から取り、合うかを確かめる。合わなければ裁定 (`members`)。
  `anchor_context` も 2 つの読みとしるしの棚卸しを通す (塩竈の斜体)
- 同じ型の資料は、1 本目で構造の見つけ方を決め、残りはその見つけ方で読んで 1 本ずつ確かめる
- 中身が同じカレンダー (板橋: 24 コースのうち中身の違うものは 15) は日付の集まりで 1 つにまとめ、地区の一覧を合わせる

### 5.2 町民カレンダー (冊子)

女川町 (32 ページ)、国立市 (60 ページ。A 地区 7〜19 ページ、B 地区 20〜32 ページ)、滑川町 (20 ページ)、瑞穂町 (24 ページ、2 か月で 1 ページ)。

### 5.3 いくつかの市町村の分を出す組合

秩父広域市町村圏組合 (秩父・皆野・長瀞・小鹿野・横瀬)、蓮田白岡衛生組合 (蓮田・白岡)、鶴ヶ島・毛呂山・越生・鳩山の 4 市町の組合のサイト (hozenkumiai.or.jp)。

- どの市町村の分かは、見出し・地区の名前・ファイルの名前で決める。発見の `features.other_muni` (ほかの市町村の名前だけがあるページ) は、その市町村の資料にしない
- 組合の資料が構成の町の一部しか書いていなければ、残りの町は別の資料を探す (台帳の待ち行列)
- 処分場への持ち込みの案内 (東京二十三区清掃一部事務組合など) は収集日ではない (`mode: dropoff`)

  同じくらい新しければ組合の資料を選ぶ (市町村のページは写しのことが多い)。違いが日付・地区に当たるときは、この順で選んだものを `version` の裁定で人が確かめ、確かめるまで違う系列は答えない
- `district_id` には、その市町村の `lg_code` を頭に付ける (秩父広域の型を使う 4 市町は、同じ大字の名前がぶつかりうる)。
  §4.1 の 9 (地区のもれと重なり) は、構成の市町村ごとに、その市町村の ABR の町字だけで見る

### 5.4 島

- 島ごとに日程が違う所は、島を地区 (`unit: island`) にする: 塩竈市の浦戸 (桂島・野々島・寒風沢・朴島。「浦戸地区」の別の PDF があり、粗大ごみの日と島ごとの時刻も別のページ)、女川町の江島
- **島の証拠**: 台帳の有人島 (`inhabited_islands`) か `nationwide/designated_islands.csv` に島がある自治体で、島が自治体の一部 (本土と島、島が 2 つ以上) なら、島ごとに次のどちらかが要る:
  (a) 島の名前 (か、島の町字の名前) が、資料の地区の文・`anchor_context`・題のどれかにある、(b) 島の町字が、町字の単位で地区の中身に入っている。
  町全体の地区 (`municipality`) だけでは、島に日付で答えない (種類 3)。理由: 塩竈の浦戸は日程が別で、町全体の表を当てると誤る。初版の確かめは、町全体の地区があると素通りしていた。
  自治体が島 1 つだけ (利島・青ヶ島) なら、町全体の地区が島の証拠になる
- 天候・欠航の順延 (塩竈の浦戸「悪天候等で…順延の場合は、翌々週6月13日」) は `contingency` で持ち、日付は消さずに答えに注意を付ける
- 島・村のページは、収集か持ち込みか (`mode`) を 2 つの読みの両方が決める (三宅は持込の日が収集の日の間に書いてある、川北の粗大ごみの持ち込み)
- 日程が公開されていない島は、地区として持ったうえで種類 3 (女川町の江島)。収集の無い島は種類 4 (竹富町の新城島(下地)・嘉弥真島など)
- 島だけの自治体 (利島村・青ヶ島村) は、村全体で 1 つの地区になりやすい。青ヶ島村は燃えるごみ・生ごみが月・水・金、燃えないごみは随時 (クリーンセンターの置場へ持ち込み) で、
  年末年始と祝日の扱いが無ければ種類 3
- 地区の図形は、町字があれば町字、無ければ N03 の陸のかたまり (台帳の `n03_comp_id`)。§4.1 の 10 で、有人島のもれを見る

### 5.5 アプリだけ・JavaScript のページ

- 発見の `app_only` 3 件は調べるとどれも誤りだった (富士見: 画像の冊子の 7 ページに表、白岡: 組合のサイト、神津島: LINE の共有ボタン)。
  `app_only` でも、ほかの候補と資料の一覧を読み取りの段でもう一度見る
- 本当にアプリだけなら、種類 3 (アプリの名前・公式ページ・窓口)。民間アプリ (5374・さんあ～る・ごみスケなど) のデータは使わない
- **自治体が公開している JavaScript の表示** (`js_view`。岡山市の kintone の公開ビュー、吉見町の SMART CMS の地区別の検索、毛呂山町・春日部市の町名の検索) の方針
  (§9 の 1 で M1 の前に決める。案):
  - 自治体が自分の公式ページから案内している表示は、公式の表とみなす (`format: js_view`)
  - 読む前に、robots.txt と、その表示のサービスの利用規約を確かめる。禁じられていれば読まない
  - 読むのは、公開のページが自分で読みにいく公開の JSON だけ。礼儀 (1 ホスト 1 秒 1 回・名乗る User-Agent・キャッシュ) は同じ。
    認証の値 (API の鍵・トークン) を送らないと返らないものは読まない。ページに埋め込まれた鍵の値は、どのファイルにも書かない
    (吉見のページには CMS の鍵が埋め込まれているので、鍵なしで読めなければ種類 3 のまま)
  - 2 つの読み: コードが JSON の項目を読み、LLM が同じレコードの生の JSON を読む。ほかの資料 (岡山の「ごみ減量・リサイクルガイド」など) があれば資料どうしも比べる。
    版の証拠 (§3.3) は、表示の中の年度の印と、公式ページのリンクの文字 (岡山「令和6年3月からの収集曜日一覧表」) で取る
  - 読むのは M2 から。岡山市 (約70万人) は政令市で、読まなければ種類 3 のまま人口の割合を大きく下げる

### 5.6 ブロック・見つからない

- 倉敷市の地区の PDF 6 本のようにブロックされたもの、robots.txt で禁止のものは取らない。回避しない
- 種類 3 (公式ページと窓口) にして、人が見るか、自治体に問い合わせる待ち行列へ。台帳に `blocked.where` と日付を残す
- 見つからない (`not_found`) は、まず女川町のような発見の取りこぼし (点数が低いだけ) を疑い、候補を全部見直す

### 5.7 年度の途中の変更・毎月の差し替え・日ごとに変わるページ

- 期間を分けて持つ (§2.2)。女川町は 10/1 から分け方が変わり、カレンダーの見出しは 4 月の印刷のまま → 品目の `official_label` を期間ごとに持ち、注を付ける
- 毎月差し替える資料 (熊谷 `R8.10.pdf`) は、1 か月の期間として読み、見張りで次の月を読む。来月の分が無いうちは、その月より先は答えない
- **日ごとに変わるページ** (鶴ヶ島の `garbage.php?mode=cal&ac=1`): パラメータが無いと取った日の月を返し、`Last-Modified` も無いので、URL と sha256 では資料を見分けられない
  - いつも年と月をつけて取る (`&year=2026&month=11`)。`source_key` は URL + パラメータ + 月 (§2.7)、`format: dynamic_month`。地区 4 × 12 か月 = 48 回
  - こういうページの先の月は、市が年末年始の変更を入れる前に、規則から機械で作られているかもしれない。だから `listed` でも、次のどちらかがそろうまで、その月は `blocked_by: provisional_month`:
    (a) その月の始まりの 60 日前より後に取った、(b) 同じ年度の別の資料 (鶴ヶ島の画像の PDF のカレンダー) と合う
  - 12・1 月は、さらに日付のある年末年始の知らせ (鶴ヶ島「祝日も収集を行います。12月29日から1月3日の収集はありません」) か、(b) の資料と合うこと
  - 鶴ヶ島の地区は線 (日光街道・関越自動車道・東武東上線) で分かれるので、日付が決まっても場所の答えは種類 2 (聞き返す)

### 5.8 変更の見張り

初版は資料ごとのバイト列の sha256 だけを見ていた。これでは、年度の途中の改訂や新しい版が **新しいファイル** で出たとき (涌谷が R7 と R8 を並べたように) 古いファイルは変わらないので見落とし、
逆に HTML のバイト列は「更新日」や動的な部分で毎回変わるので、自治体ごと答えを止めてしまう。

- **見張るもの** (`watch`):
  - 資料ごとの `content_sha256`: HTML は本文の範囲 (§3.2) の文字と表を正規化したもの (「更新日」「閲覧数」の行は除く)。
    PDF は文字層と、図形・画像の要約 (ページごとの矩形・線の数と画像の sha256)。バイト列の `sha256` は記録だけに使う
  - 案内のページの `link_set`: 日程らしいリンク (段 1 の型が `date_grid`・`district_list`・`rule_table` のもの) の (href, リンクの文字, `anchor_context` の文字) を正規化した集まりの sha256
- **変わったとき**:
  - 資料の中身が変わった → その資料から作った系列を `blocked_by: ["source_changed"]` で止め、読み直して確かめ (§4.1) を通るまで答えない
  - 案内のページに日程らしい新しいリンクが出た → リンクの文字・ファイルの名前の年の印を見る。今の期間の印 (訂正版・差し替え) か、年の印が無ければ、今の期間の系列を止めて読み直す。
    次の期間の印なら、今の答えは続け、次の期間を読む
  - 日程らしいリンクが消えた → その資料から作った系列を止める
- **いつ見るか**: 普段は今の `monitor.py` の間隔。加えて、11〜12 月 (年末年始の知らせ。`deferred` のある所は週 2 回)、2〜3 月 (新しい年度の資料)、毎月差し替えの資料 (熊谷) は月の初め
- `deferred` の知らせを読んだら、その `unknown_ranges` を外し、日付で答えられるかを確かめ直す (足立・大田・渋谷)。知らせも 1 つの資料として 2 つの読みと確かめを通す

## 9. 決めてほしいこと

1. **自治体の JavaScript の表示 (M1 の前に決める)**: §5.5 の案 (公式の表とみなし、robots.txt と表示のサービスの利用規約を確かめてから、公開の JSON を読む。
   認証の値を送らないと返らないものは読まない) でよいか。読むなら岡山市 (約70万人) が M2 で種類 3 から 1・2 に上がりうる。読まなければ種類 3 のまま
2. **裁定の強いモデル**: Claude Opus 5.5 を API で使うか (文の 1 件 約 $0.05・画像の 1 件 約 $0.2〜0.3、全国で $1K〜7K の見込み)、ほかの道か
3. **人の手間**: 300〜750 時間 (公開の前の監査 150〜250 時間を含む) と、公開のあとの監査 月 7〜10 時間を、誰がどう持つか。
   単位ごと 300 系列の監査を減らすと、誤りの上限の約束 (1%) をゆるめることになる
4. **japan-gomi-data**: 比べるためだけに使うか、取り込むか (計画 §4 の 3)。取り込むなら出典の表示と、向こうの推定 (岡山の年末年始) の扱い
5. **問い合わせ**: 自治体への問い合わせを誰がどの形で出すか (人の作業の待ち行列。計画 §3 の 6)
6. **線で分ける地区** (道路・線路の片側): 線の図形の出典 (国土地理院の基盤地図情報など) を入れて種類 2 から 1 に上げるか、聞き返すままにするか
7. **期間の書いていない常設の資料** (大衡村の曜日の表、仙台市の「令和7年7月1日」現在の表、2023 年に作った豊島の規則): 公式ページが同じ資料を載せていることを見張りで確かめている間は、
   日付で答えてよいか。今の案では答えない (規則として返す)
8. **「祝日」とだけ書いた所の振替休日・国民の休日**: 今の案では、その日だけ不明 (FY2026 で 1 系列あたり 0〜3 日)。「祝日」に含めてよいと決めれば、この不明が減る
9. **月ごとの規則の日が祝日・休みで消える月** (§2.5 の 4 の (D)): 今の案では、ほかの回の数え方が書いていなければ、その月を不明にする (1 系列 1 年に 0〜2 か月)。
   「祝日は収集しません」は数え直さない意味だと決めてよければ、祝日の分の不明が消える (施設の点検・お盆の休みは残す)
10. **振り替えの文からの推し量り** (羽咋「1/1(金)は休みのため 1/5(火)に特別収集します」): 今の案では、ほかの回の数え方を推し量らず、窓 W を不明にする。
   人が「振り替えの文だけで、ほかに休みの期間の文が無い品目は、ほかの回をずらさない」を決まりとして認めるなら、版つきの決まりにして、印字のある所 (金沢・草加) で外れないかを先に確かめる
